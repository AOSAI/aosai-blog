实例归一化：Instance Norm

约 2531 字大约 8 分钟

归一化InstanceNorm

1. 为什么需要实例归一化

风格迁移（Style Transfer）的任务是：把一张照片的"内容"和另一张画的"风格"结合起来。比如把一张狗的照片变成梵高画风的狗。

2015年，Gatys 等人第一次用 CNN 实现了风格迁移（arXiv:1508.06576）。他们发现：VGG 网络的浅层能提取"风格"（纹理、颜色分布），深层能提取"内容"（物体结构）。

通过优化一张白噪声图片，让它在浅层匹配目标风格的统计量、在深层匹配源图片的内容表示，就能生成风格化图片。效果惊艳，但极慢，每张图要迭代几百步，跑好几分钟。

1.1 风格迁移的困境

2016年，Johnson 等人（arXiv:1603.08155）提出了"快速风格迁移"：用一个前馈网络直接学习"原图→风格化图"的映射，推理只需 0.03 秒。这个网络用了 Batch Normalization。

但研究者们发现一个问题：用 BN 做归一化时，生成的图片会"糊掉"。

"糊掉"具体是什么样？看上面的 Fig.1：

  • 色彩变淡（梵高那种浓烈的黄色和蓝色变得灰蒙蒙）
  • 纹理丢失（笔触、旋涡变得模糊）
  • 不同风格的输出趋于相似。

原因在于：BN 是跨样本计算统计量的。假设训练时把一张猫图和一张狗图放在同一个 batch 里，猫的"毛茸茸"风格和狗的"忠诚"风格会被平均掉。

更关键的是，风格信息主要藏在特征图的通道统计量中（均值和方差），BN 把这些统计量混在一起，风格就丢失了。

1.2 实例归一化的诞生

2016年，Ulyanov、Vedaldi 和 Lempitsky 提出了 Instance Normalization（arXiv:1607.08022）。他们的发现非常简单：把 BN 换成 IN，风格迁移的效果就显著提升了。

从 Fig.2 的 loss 曲线可以看到，IN 的训练 loss 下降更快、更稳定。IN 的输出结果色彩鲜艳、纹理清晰，和 BN 的"糊掉"效果形成鲜明对比。

核心思想：对每个样本的每个通道单独归一化。每张图片的每个通道都有自己的均值和方差，互不干扰。这样每张图片的风格信息都被独立地保留下来。

2. InstanceNorm 的原理与推导

2.1 三种归一化：一个对比看懂差异

想象一摞油画摆在桌上。每幅画是一个样本（N），每幅画由红、绿、蓝三个颜色层叠在一起，每层是一个 H×W 的网格。

  • BN：把所有画的红色层全部抽出来，混成一大张，算一个平均亮度。问题是：一幅日落画（红色很多）和一幅海洋画（蓝色很多）的红色统计量被混在一起，各自的风格就丢了。
  • LN：拿起一幅画，但不按颜色层分开，而是把红绿蓝三层压成一张扁平的纸来算平均。问题是：不同颜色混在一起算，不合理。
  • IN：拿起一幅画，单独抽出它的红色层，算这层的平均亮度；再单独抽出绿色层、蓝色层，各自算。每幅画的每个颜色层都独立处理，互不干扰。

用数字来感受一下。假设一个 mini-batch 有 2 张 2×2 的小图，每张图有 2 个通道：

样本1 通道0: [[1, 2],    样本1 通道1: [[5, 6],
             [3, 4]]                  [7, 8]]

样本2 通道0: [[9, 10],   样本2 通道1: [[13, 14],
              [11, 12]]               [15, 16]]

BN 怎么算？ 跨所有样本，按通道归一化。对通道 0，把样本 1 和样本 2 的值混在一起 [1,2,3,4,9,10,11,12]，算出一个 μ 和 σ²。每个通道只有一个统计量。

LN 怎么算？ 按样本，跨所有通道归一化。对样本 1，把通道 0 和通道 1 的值混在一起 [1,2,3,4,5,6,7,8]，算出一个 μ 和 σ²。每个样本只有一个统计量。

IN 怎么算？ 对样本 1 的通道 0，只看这个 2×2 的切片 [1,2,3,4]，算出 μ=2.5, σ²=1.25。样本 2 不参与，通道 1 也不参与。每个 (样本, 通道) 对都有自己的统计量。

一句话总结：BN 看的是"同一个通道在不同样本上的分布"，LN 看的是"同一个样本在不同特征上的分布"，IN 看的是"同一个样本的同一个通道在空间位置上的分布"。

2.2 数学公式

给定输入 x∈RN×C×H×Wx \in \mathbb{R}^{N \times C \times H \times W}x∈RN×C×H×W，IN 对每个 (n,c)(n, c)(n,c) 对单独归一化：

第一步：算均值 μ——这个通道在空间上有多"亮"

μnc=1HW∑h=1H∑w=1Wxnchw\mu_{nc} = \frac{1}{HW}\sum_{h=1}^{H}\sum_{w=1}^{W}x_{nchw} μnc​=HW1​h=1∑H​w=1∑W​xnchw​

比如一张 4×4 的灰度图（一个通道），9 个像素值的均值就是 μ。

第二步：算方差 σ²——这个通道在空间上有多"散"

σnc2=1HW∑h=1H∑w=1W(xnchw−μnc)2\sigma_{nc}^2 = \frac{1}{HW}\sum_{h=1}^{H}\sum_{w=1}^{W}(x_{nchw} - \mu_{nc})^2 σnc2​=HW1​h=1∑H​w=1∑W​(xnchw​−μnc​)2

第三步：归一化并缩放

ynchw=xnchw−μncσnc2+ϵ⋅γc+βcy_{nchw} = \frac{x_{nchw} - \mu_{nc}}{\sqrt{\sigma_{nc}^2 + \epsilon}} \cdot \gamma_c + \beta_c ynchw​=σnc2​+ϵ​xnchw​−μnc​​⋅γc​+βc​

其中 ϵ\epsilonϵ 是防止除零的小常数，γ\gammaγ 和 β\betaβ 是可学习参数（和 BN、LN 一样）。

注意：IN 的均值和方差下标是 (n,c)(n, c)(n,c)——每个样本的每个通道独立计算。而 BN 的下标只有 ccc（跨样本），LN 的下标只有 nnn（跨特征）。

你可能会问：μ 和 σ² 都有 n 下标，为什么 γ 和 β 只有 c？

因为 μ 和 σ² 是从数据中算出来的统计量，每张图、每个通道都不一样，所以需要 (n,c)(n, c)(n,c) 两个下标。而 γ 和 β 是网络层学出来的参数，和具体输入无关。它们的含义是"对于第 c 个通道，网络认为最佳的缩放和偏移是多少"。

你不会因为今天看到的是猫图就换一把尺子、明天看到的是狗图就换另一把尺子。尺子（γ、β）是统一的，量出来的结果（μ、σ²）才因图而异。

2.3 为什么 IN 适合风格迁移

风格迁移中，我们希望：

  1. 保留内容信息：图片的结构、物体形状
  2. 转移风格信息：颜色、纹理、笔触

风格信息主要由特征图的通道统计量（均值、方差）编码。IN 对每个通道独立归一化，相当于：

  • 去掉了原始图片的"风格"（通过减去均值、除以方差）
  • 保留了"内容"（空间结构不变）
  • 然后可以用目标风格的统计量重新缩放

这就是为什么 IN 能在风格迁移中表现出色——它精确地控制了"去掉什么、保留什么"。

3. PyTorch 实现

3.1 基本用法

InstanceNorm 的命名和 BatchNorm 一样，1d/2d/3d 指的是空间维度：

类名空间维度输入形状适用场景
InstanceNorm1d1D(N, C, L)序列数据
InstanceNorm2d2D(N, C, H, W)图像（最常用）
InstanceNorm3d3D(N, C, D, H, W)视频、3D 数据
import torch.nn as nn

# 图像归一化（最常用）
# 注意：这里的 num_features 是通道数 C，不是 batch size 的 N
in2d = nn.InstanceNorm2d(num_features=64)

# 常用可选参数
in2d = nn.InstanceNorm2d(
    num_features=64,
    eps=1e-5,              # 防止除零，默认 1e-5
    momentum=0.1,          # running statistics 更新速度，默认 0.1
    affine=True,           # 是否启用可学习参数 γ 和 β，默认 True
    track_running_stats=True  # 是否跟踪 running mean/var，默认 True
)

和 BN 的区别：IN 在训练和推理时的行为完全一样（都用当前输入的统计量），所以 momentum 和 track_running_stats 参数实际上不起作用。这是 IN 的一个优势：不需要维护 running statistics。

3.2 在风格迁移网络中使用

下面用一个简化的编码器-解码器网络演示 IN 的用法：

import torch.nn as nn

class FastStyleTransfer(nn.Module):
    def __init__(self):
        super().__init__()
        # 编码器：提取特征
        self.encoder = nn.Sequential(
            nn.Conv2d(3, 32, 3, padding=1),
            nn.InstanceNorm2d(32),
            nn.ReLU(),
            nn.Conv2d(32, 64, 3, padding=1),
            nn.InstanceNorm2d(64),
            nn.ReLU(),
        )
        # 解码器：重建图片
        self.decoder = nn.Sequential(
            nn.ConvTranspose2d(64, 32, 3, stride=2, padding=1, output_padding=1),
            nn.ReLU(),
            nn.Conv2d(32, 3, 3, padding=1),
        )

    def forward(self, x):
        x = self.encoder(x)   # IN 在这里独立归一化每个通道
        x = self.decoder(x)
        return x

IN 放在卷积层之后、激活函数之前。和 BN 的位置一样，每个通道独立归一化，保留各自的空间统计信息。

4. 总结与扩展

4.1 优点

  1. 不依赖 batch size：每个样本的每个通道独立归一化
  2. 训练和推理行为一致：不需要维护 running statistics，不需要 model.eval() 切换
  3. 适合风格迁移和图像生成：精确控制每个通道的统计量
  4. 可学习参数 γ 和 β：和 BN、LN 一样，让网络有"反悔"的能力

4.2 缺点与注意事项

  1. 归一化粒度太细：每个通道独立计算，丢失了通道间的关系。在分类、检测等任务中效果不如 BN
  2. 主要适用于图像任务：IN 需要空间维度（H, W），Transformer 中用不了

4.3 使用场景：IN 的兴起与没落

时代代表方法仓库（Stars）归一化为什么选它
2015Gatys et al. 基于优化—无需归一化逐图迭代，不是前馈网络
2016Johnson et al. 快速风格迁移fast-style-transfer（11k）BN当时 BN 是标配
2016Ulyanov et al. IN 论文texture_nets（1.2k）INBN 糊掉，IN 修好了
2019StyleGAN2NVlabs/stylegan2（11k）AdaIN（IN 的升级版）支持风格混合，成为 GAN 风格迁移的标杆
2023InST（扩散模型风格迁移）zyxElsa/InST（587）GN（继承预训练扩散模型）扩散模型时代，复用预训练模型的归一化

一句话记住：IN 诞生于风格迁移，精确解决了"BN 把不同图的风格统计量平均掉"的问题。从 CycleGAN 到 StyleGAN2，IN 一直是风格迁移的标配。到了扩散模型时代，风格迁移方法（如 InST）不再自己设计归一化层，而是直接复用预训练模型的 GN。
