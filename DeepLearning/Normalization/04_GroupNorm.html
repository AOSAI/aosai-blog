组归一化：Group Norm

约 3194 字大约 11 分钟

归一化GroupNorm

1. 组归一化的来历

1.1 BN 的困境：小 batch 的挑战

2015-2017 年，目标检测和语义分割是计算机视觉的热门任务。和图像分类不同，这些任务需要检测/分割图中的小物体，所以输入图像不能缩得太小。当时的典型输入尺寸：

模型年份输入尺寸典型 batch size
Faster R-CNN2015短边 600 像素1-2
Mask R-CNN2017短边 800 像素1-2
YOLOv32018416×416 或 608×6081-4
SSD2016300×300 或 512×5128-16

问题是：2017 年的 GPU 显存普遍只有 8-12 GB（GTX 1080 Ti = 11 GB）。一张 800×800 的图片经过 ResNet-50 后，feature map 还有约 25×25×2048，显存压力很大。batch size 只能设为 1-2。

这就让 Batch Normalization 崩了：

  • batch size=1 时，均值和方差就是这张图自己的统计量，完全失去了"跨样本归一化"的意义
  • batch size=2 时，两个样本的统计量互相干扰，结果也不靠谱
  • 更关键的是：训练时用 batch 统计量，推理时用全局 running statistics，行为不一致

Kaiming He 等人在 2018 年的论文中（arXiv:1803.08494）明确指出："BN 的 batch size 不能太小，否则效果急剧下降"。

1.2 LN 和 IN 的局限

你可能会问：LN 和 IN 都不依赖 batch size，为什么不直接用它们？

那是因为：LN 和 IN 都丢失了通道间的关系。

  • LN：对单个样本，把它的所有通道混在一起算一个均值和方差（跨通道归一化）。比如一个特征图有 256 个通道，LN 会对这一个样本的 256 个通道的值全部摊平，算一个统计量。通道之间的区分完全消失了。
  • IN：每个通道独立算均值和方差。256 个通道，256 个统计量，互不干扰。看起来更精细，但问题是：通道之间的关系也被完全切断了。

在检测和分割任务中，通道之间的关系很重要。比如"边缘检测通道"和"纹理检测通道"之间可能存在互补关系，如果把它们分开归一化，这种关系就丢失了。

1.3 组归一化的诞生

2018年，Kaiming He、Xiangyu Zhang、Shaoqing Ren 和 Jian Sun 提出了 Group Normalization（arXiv:1803.08494）。他们的核心想法很简洁：把通道分成若干组，每组内部计算统计量。

具体来说：

  • 输入有 C 个通道
  • 把这 C 个通道分成 G 组，每组有 C/G 个通道
  • 对每组内的通道，独立计算均值和方差
  • 每个样本单独处理，不跨样本

这样做的好处：

  1. 不依赖 batch size：每个样本独立计算，和 BN 的 batch 统计量无关
  2. 保留通道间的关系：同一组内的通道一起归一化，保留了它们的关联
  3. 训练和推理行为一致：不需要维护 running statistics

2. GroupNorm 的原理与推导

2.1 四种归一化：一个统一的视角

假设输入是一个 4D 张量，形状为 (N,C,H,W)(N, C, H, W)(N,C,H,W)：

  • NNN：batch size（样本数）
  • CCC：通道数
  • H,WH, WH,W：空间维度（高、宽）

四种归一化的区别，本质上是在哪些维度上计算统计量：

输入形状：(N, C, H, W)

BN：对每个通道，跨所有样本和空间位置归一化
    统计量维度：(C,)
    每个通道一个均值和方差

LN：对每个样本，跨所有通道和空间位置归一化
    统计量维度：(N,)
    每个样本一个均值和方差

IN：对每个样本的每个通道，跨空间位置归一化
    统计量维度：(N, C)
    每个样本的每个通道一个均值和方差

GN：对每个样本的每个通道组，跨组内通道和空间位置归一化
    统计量维度：(N, G)
    每个样本的每个组一个均值和方差

用一个比喻来理解：假设你有 100 个学生（样本），每个学生有 4 门课（通道）的成绩。

  • BN：按科目算。所有学生的数学成绩放一起算均值，所有学生的语文成绩放一起算均值...
  • LN：按学生算。每个学生把 4 门课的成绩混在一起，算一个总均值
  • IN：按学生+科目算。每个学生的每门课独立看，但这门课只有这一个数据点，没法算均值（所以在空间维度上算）
  • GN：按学生+科目组算。把 4 门课分成 2 组（比如理科组和文科组），每个学生的每组成绩放一起算均值

注意：GN 的均值和方差下标是 (n,g)(n, g)(n,g)，即每个样本的每个组独立计算。而 BN 的下标只有 ccc（跨样本），LN 的下标只有 nnn（跨特征），IN 的下标是 (n,c)(n, c)(n,c)（每个通道）。

2.3 GN 与其他归一化的关系

GN 有一个非常优雅的性质：通过调整组数 G，GN 可以退化为 LN 或 IN。

  • 当 G=1G=1G=1 时：所有通道在同一组，GN 退化为 LayerNorm
  • 当 G=CG=CG=C 时：每个通道一组，GN 退化为 InstanceNorm

这意味着 GN 是 LN 和 IN 的推广。LN 和 IN 是 GN 的两个极端特例。

G=1         → LayerNorm（所有通道一起算）
G=C         → InstanceNorm（每个通道独立算）
1 < G < C   → GroupNorm（折中方案）

这个关系很重要：它说明 GN 的设计空间包含了 LN 和 IN，可以通过调整 G 来找到最优的归一化粒度。

3. PyTorch 实现

3.1 基本用法

GroupNorm 的 API 非常简洁：

import torch.nn as nn

# 基本用法
gn = nn.GroupNorm(
    num_groups=32,      # 组数 G
    num_channels=64,    # 通道数 C（必须能被 G 整除）

    # 常用可选参数：
    eps=1e-5,              # 防止除零，默认 1e-5
    affine=True,           # 是否启用可学习参数 γ 和 β，默认 True
)

注意事项：

  • num_channels 必须能被 num_groups 整除。比如 C=64 时，G 可以是 1、2、4、8、16、32、64
  • 常用的默认值是 G=32，这是原论文推荐的配置
  • affine=True（默认）会启用可学习参数 γ\gammaγ 和 β\betaβ

和 BN 的区别：GN 在训练和推理时的行为完全一样（都用当前输入的统计量），不需要维护 running statistics。这是 GN 的一个优势，即不需要 model.eval() 切换模式。

3.2 在检测/分割网络中使用

GN 最典型的应用场景是目标检测和语义分割。以 Faster R-CNN 为例：

import torch.nn as nn

class ResBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1)
        # 检测/分割任务中，batch size 通常很小（1-2）
        # 用 GN 替代 BN，避免小 batch 导致的统计量不准确
        self.gn = nn.GroupNorm(32, channels)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1)

    def forward(self, x):
        h = self.conv1(x)
        h = self.gn(h)      # GN 在卷积后、激活前
        h = nn.functional.relu(h)
        h = self.conv2(h)
        h = self.gn(h)
        h = nn.functional.relu(h)
        return x + h

GN 放在卷积层之后、激活函数之前，和 BN 的位置一样。每个通道组独立归一化，保留组内的通道关系。

4. 总结与知识扩展

4.1 优缺点与注意事项

  • 不依赖 batch size：每个样本独立计算，batch size=1 也能正常工作
  • 保留通道间的关系：同一组内的通道一起归一化，不丢失通道关联
  • 训练和推理行为一致：不需要维护 running statistics，不需要 model.eval() 切换
  • 兼容性强：可以看作 LN 和 IN 的推广，通过 G 参数灵活调整
  1. 组数 G 需要手动设置：通常 G=32 是一个不错的默认值，但不同任务可能需要调整
  2. 图像分类任务中 BN 仍然更好：BN 的跨样本统计量在大 batch 下提供了隐式正则化，这是 GN 不具备的
  3. 通道数必须能被 G 整除：如果通道数不是 G 的倍数，需要调整 G 或通道数

4.2 使用场景

任务推荐为什么选它而不选 GN
目标检测GNGN 的主场，batch size 小时 GN 比 BN 更稳定
语义分割GN同上，且 GN 保留通道间关系
图像分类BNbatch size 大时，BN 的跨样本统计量提供隐式正则化，GN 不具备
风格迁移ININ 每个通道独立归一化，更彻底地保留每个样本的风格信息；GN 的分组会把不同风格的通道混在一起
序列建模LNLN 跨通道归一化，适合 1D 序列；GN 需要空间维度（H, W），在 1D 序列上效果不好

一句话记住：GN 是 LN 和 IN 的折中，把通道分组，既不丢失通道关系，又不依赖 batch size。检测和分割是它的主场。

4.3 网络加深时，新增的通道是空的吗？

简短回答：不是的。新增的通道是通过 1×1 卷积从旧通道学习出来的组合，不是空的，也不是固定不变的。

具体过程（以 ResNet 为例）：

下采样前：128 通道，256×256 空间
下采样后：256 通道，128×128 空间

这个变化是通过一个 1×1 卷积（stride=2） 完成的：

  1. 空间维度减半：stride=2 的卷积把 256×256 变成 128×128
  2. 通道维度翻倍：输出 256 个通道，每个通道是输入 128 个通道的线性组合
  3. 所有参数都是可学习的：包括卷积核的权重和偏置

所以：

  • 原来的 128 个通道不是"固定"的，而是被 1×1 卷积重新组合了
  • 新增的 128 个通道不是"空"的，而是学习到了不同的特征组合
  • 最终的 256 个通道各自负责不同的特征：有的学边缘，有的学纹理，有的学结构...

打个比方：想象你有 128 种颜料（旧通道），现在要调出 256 种新颜色（新通道）。每种新颜色都是旧颜料的混合配方（1×1 卷积的权重）。新颜色不是"空"的，而是旧颜料的不同组合。

关键点：通道是可学习的特征表示，不是固定的"容器"。网络通过训练，自动学习每个通道应该负责什么特征。这就是为什么我们不需要手动设计每个通道的功能——网络会自己找到最优的特征组合。

4.4 GN 的组是怎么划分的？

简短回答：连续分组，不是智能分组。GN 不关心通道的语义，只是按编号顺序切分。

具体方式：假设 C=8 个通道，G=4 个组：

通道编号：[0, 1, 2, 3, 4, 5, 6, 7]
分组结果：[0,1] [2,3] [4,5] [6,7]
         组0   组1   组2   组3

就是按通道编号顺序，连续切分。没有"纹理通道分一组、结构通道分一组"这种设计。

为什么这样做能工作？

虽然分组方式看起来很"笨"，但在实践中效果不错，原因是：相邻通道倾向于学习相似的特征。

在 CNN 中，卷积核是通过梯度下降学习的。相邻的卷积核（编号相近的通道）往往捕捉相似的模式（比如都是边缘检测器，只是方向不同）。所以连续分组是一个合理的启发式方法。

硬约束：C 必须能被 G 整除。

  • C=128, G=32 → 每组 4 个通道，可以
  • C=112, G=32 → 每组 3.5 个通道，不行
  • C=112 时，可用的 G 值是：1, 2, 4, 7, 8, 14, 16, 28, 56, 112

这是一个局限性：GN 不关心"纹理"还是"结构"，它只看通道编号。即使纹理和结构是完全不同的特征，只要它们的通道编号相邻，就会被分到同一组。理论上，如果能根据通道的相关性做智能分组，效果可能更好。但 GN 选择了简单方案，因为在实践中已经足够好。

2026 年现状：PyTorch 的 nn.GroupNorm 实现至今未变，仍然使用连续分组。没有官方的"智能分组"变体。
