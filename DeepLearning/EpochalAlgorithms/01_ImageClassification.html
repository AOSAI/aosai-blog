图像分类算法：流程稳定

约 3982 字大约 13 分钟

跨时代算法图像分类分类任务

1. 分类任务是什么？

分类任务的目标很简单：给一个输入，判断它属于哪个类别。

如果只有两个类别，就是二分类；如果有很多类别，就是多分类。深度学习里的图像分类，就是把一张图片放进模型，让模型在一组固定类别里做选择：猫、狗、汽车、飞机……

但分类任务不是一上来就从图片开始的。先把维度降到最低，看它的本质会更清楚。

1.1 在 1 维空间中的分类

1 维空间里，每个样本只有一个数字。

比如我们只看一个人的身高，要判断他是“小孩”还是“成年人”。这时分类边界可以很简单：找一个阈值。

身高 < 140cm → 小孩
身高 ≥ 140cm → 成年人

这个阈值就是分类边界。边界左边是一类，右边是另一类。

1.2 在 2 维空间中的分类

如果每个样本有两个数字，比如身高和体重，就进入了 2 维空间。

这时一个阈值不够了，我们需要一条线，把平面上的点分成两边。线的一边是类别 A，另一边是类别 B。

1.3 在 3 维空间中的分类

如果每个样本有三个数字，比如身高、体重、年龄，就进入了 3 维空间。

这时分类边界从一条线变成了一个平面。平面的一边是一类，另一边是另一类。

维度继续升高后，我们就没法画出来了。但逻辑没有变：分类任务一直在找一个边界，把不同类别分开。

图像分类也是这样。只不过输入不再是 1 个数字，也不是 3 个数字，而是一整张图片。模型会先把整张图编码成一个特征向量，再根据这个向量判断：这张图更像猫、狗，还是汽车。

2. 图像分类的算法抽象

先给图像分类算法下一个定义：

图像分类算法，就是学习一个函数 f(x)f(x)f(x)，把一张图像 xxx 映射成一组类别概率。

如果类别集合是猫、狗、汽车，那么模型最后要输出的不是一句话，而是一个概率分布：

P(猫 | 图像), P(狗 | 图像), P(汽车 | 图像)

这组概率加起来等于 1。谁的概率最大，模型就预测这张图属于谁。

所以图像分类的算法抽象可以写成：

输入：一张图像 x
输出：每个类别的概率 P(y | x)
目标：让真实类别的概率尽可能高

这就是分类任务在深度学习里的基本算法定义。后面的网络结构、损失函数、优化器，都是围绕这个定义服务的。从这个定义出发，图像分类的训练流程就很稳定：

2.1 训练阶段：模型在循环里变好

拆开来看：

  1. 图像：输入是一张图片，形状通常是 (C, H, W)，比如 RGB 图像就是 3 个通道。
  2. 特征提取器：CNN、ResNet、ViT 都是在这里工作，把像素变成更有用的特征。
  3. logits：模型给每个类别输出一个分数。
  4. 交叉熵损失：看真实类别的分数有没有被模型推高。
  5. 反向传播：根据损失计算梯度。
  6. 优化器更新参数：参数更新后，模型进入下一批训练。

训练不是走完一条线就结束，而是一个循环。每一批图片都会让模型调整一次参数；一个 epoch 结束后，模型会继续进入下一个 epoch，直到训练轮数结束。

2.2 预测阶段：训练结束后再输出类别

训练结束后，模型参数固定下来。此时再输入一张新图片，模型还是先输出 logits，然后用 Softmax 把 logits 变成类别概率。

图像 → 训练好的模型 → logits → Softmax → 类别概率 → 预测类别

所以要分清两件事：

  • 训练时：重点是用损失函数和反向传播更新模型。
  • 预测时：重点是把 logits 变成概率，再取概率最大的类别。

这就是图像分类最稳定的地方：后来的论文大多在改特征提取器，而不是改整套训练闭环。

3. 图像分类里的固定组件

图像分类的算法定义很稳定，所以很多组件也长期稳定。它们不是没有替代方案，而是默认组合已经很成熟。

3.1 输出形式：logits + Softmax

模型不会直接输出“猫”这个字。它会先给每个类别打一个分数，这个分数叫 logit。比如一张猫图进来，模型可能输出：

类别小猫小狗汽车
logit5.21.1-0.8

logit 可以比较大小，但它还不是概率。5.2 比 1.1 大，说明模型更倾向于“猫”，但 5.2 本身不能解释成“猫的概率是 5.2”。所以预测时需要 Softmax：

logits → Softmax → 概率

Softmax 会把所有类别的分数变成一组概率，并且这些概率加起来等于 1。

类别小猫小狗汽车
概率0.970.020.01

最后预测类别时，取概率最大的那个类别就行。

3.2 损失函数：CrossEntropyLoss

分类任务当然也在比较“预测”和“真实标签”的差距。只是这个差距，不是回归任务里的那种：

预测值 - 真实值

因为分类标签不是连续数字。“猫”不是 1.0，“狗”也不是 2.0，它们只是类别名字。模型真正输出的是一组概率。如果真实标签是“猫”，我们希望模型输出：

类别猫狗汽车
理想概率100

这叫 one-hot 标签。它的意思是：真实类别那一项应该尽量接近 1，其他类别应该尽量接近 0。所以分类任务真正关心的是：

真实类别的概率有没有被模型推高？

如果真实类别是“猫”，模型给“猫”的概率越接近 1，损失就越小；模型给“猫”的概率越接近 0，损失就越大。交叉熵损失 正好做这件事：

  • 真实类别概率是 0.95：基本猜对，损失很小。
  • 真实类别概率是 0.50：模型不太确定，损失中等。
  • 真实类别概率是 0.01：模型几乎猜错，损失很大。

所以在图像分类里，常见组合就是：

logits + CrossEntropyLoss

这里有一个 PyTorch 细节很重要：nn.CrossEntropyLoss() 内部已经包含了 LogSoftmax。所以训练时一般不要先手动写 Softmax，直接把 logits 交给损失函数就行。

logits = model(images)
loss = criterion(logits, labels)

3.3 归一化：CNN 里长期以 BatchNorm 为主

图像分类模型通常会堆很多层卷积。层数一深，每一层看到的数据分布就容易变化，训练会变得不稳定。

所以 CNN 分类模型里，BatchNorm 长期是默认选择。它放在卷积层附近，把一批数据的激活值拉回比较稳定的范围，让模型更容易训练。

常见结构是：

Conv → BatchNorm → ReLU

后来 ViT 这类 Transformer 结构更多使用 LayerNorm，但在 CNN 图像分类这条线里，BatchNorm 仍然是最经典的归一化方式。

3.4 优化器：位置固定，选择有演进

优化器负责把梯度真正变成参数更新。它的位置很固定：

loss.backward() → optimizer.step()

一轮训练可以写成很短的代码：

for images, labels in dataloader:
    logits = model(images)
    loss = criterion(logits, labels)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

对应到流程上，就是：

  1. 输入一批图片
  2. 模型输出 logits
  3. 交叉熵计算损失
  4. 反向传播计算梯度
  5. 优化器更新参数，模型变成一个新版本
  6. 下一批图片继续进入这个新版本模型
  7. 重复很多轮，直到所有 epoch 结束

优化器本身有演进：早期常用 SGD，后来 Adam、AdamW 也很常见。但它没有改变图像分类的任务定义，只是在回答一个问题：参数应该怎么更新得更快、更稳？

训练结束后，才进入真正的预测流程：

logits = model(image)
prob = torch.softmax(logits, dim=1)
pred = prob.argmax(dim=1)

这时模型不再更新参数，只输出最终类别。

4. 图像分类里的主要变量：网络结构

既然图像分类的算法定义和训练闭环这么稳定，为什么论文还在不断更新？答案是：主要在改特征提取器。

图像 → 特征提取器 → logits

2015 年之后，图像分类的主战场逐渐从“怎样设计一个更强的 CNN”，转向了一个更大的问题：

用什么方式，把一张图变成好用的视觉特征？

这条线可以按真实生态分成三段。

4.1 2015-2019：监督训练的 CNN backbone 仍是主力

2015 年之后，图像分类最重要的基线是 ResNet。它不是因为“更深”这两个字重要，而是因为它变成了后面很多视觉任务的默认骨干网络。当时的常见流程很直接：

ImageNet 有标签数据
→ 训练 CNN 分类器
→ 去掉最后的分类头
→ 把 CNN 当作下游任务的特征提取器

这就是为什么 ResNet 不只是一个分类模型。它更像一个视觉特征工厂：检测、分割、检索，都可以先拿它做 backbone。

工业界还关心速度和部署，于是 MobileNet、EfficientNet 这类模型变得重要。它们的共同目标不是单纯刷新分类准确率，而是在准确率、延迟、参数量之间找平衡。

所以这一阶段可以这样概括：

  • ResNet：把 CNN backbone 变成稳定底座。
  • MobileNet：让分类模型能跑到移动端。
  • EfficientNet：系统地平衡深度、宽度、分辨率和算力。

4.2 2020-2021：Transformer 开始替代 CNN backbone

2020 年，ViT 把图像分类的特征提取器换了一种写法：不再从卷积开始，而是把图片切成 patch，把 patch 当成 token。

图像 → patch 序列 → Transformer → 分类 token → logits

这一步很关键。分类算法没有变，还是输出 logits，还是可以用交叉熵训练；但中间的特征提取器从 CNN 换成了 Transformer。

DeiT 解决了另一个现实问题：原始 ViT 很吃数据和算力，普通 ImageNet 训练不一定够。DeiT 通过数据增强和蒸馏，让 Transformer 在 ImageNet-1K 上也能训练得比较好。

Swin Transformer 又把层级结构和局部窗口引回来，让 Transformer 不只适合分类，也适合检测、分割这类需要空间细节的任务。它的官方代码在视觉社区里也很常用。

这一阶段的重点是：

  • ViT：证明 Transformer 可以直接做图像分类。
  • DeiT：让 ViT 更容易在常规数据规模上训练。
  • Swin：让 Transformer 成为通用视觉 backbone。

4.3 2021 之后：重点从“训练分类器”转向“预训练视觉表征”

再往后看，很多热门工作已经不只是“训练一个 ImageNet 分类器”了，而是先训练一个强大的视觉编码器，再拿它去做分类、检索、检测、分割。这时，图像分类更像一个评测方式，而不是唯一目标。

CLIP 是一个代表。它不是只用“图片-类别标签”训练，而是用“图片-文字”配对训练。预测时，可以把类别写成文本，比如 “a photo of a cat”，再比较图片特征和文本特征的相似度。CLIP 的论文和代码都非常有影响力。

传统分类：图像 → 类别概率
CLIP：图像特征 ↔ 文本特征

MAE 走的是自监督路线：遮住图片中的大部分 patch，让模型重建被遮住的部分。它不靠人工标签，也能学到可迁移的视觉特征。

DINO 和 DINOv2 也很重要。它们强调“不用人工标签，也能学到强视觉特征”。DINOv2 的目标更接近“通用视觉特征”，代码生态也很活跃。

这一阶段的变化，不只是网络结构变了，训练目标也变了：

  • 以前：用 ImageNet 标签训练分类器。
  • 现在：先用大规模图文、自监督或弱监督数据训练视觉编码器。
  • 分类：变成下游评测或应用方式之一。

4.4 抽象总结：现在变的是“视觉编码器从哪里来”

如果只看早期 CNN，会以为图像分类论文主要在改“网络结构”。但看 2015 之后到现在，变化更准确地说是：

图像分类的核心变量，从“设计一个 CNN”，变成了“选择或预训练一个视觉编码器”。

可以这样对照：

阶段代表工作核心变化
监督 CNN backboneResNet、MobileNet、EfficientNet用有标签数据训练分类 backbone
Transformer backboneViT、DeiT、Swin用 Transformer 替代 CNN 做视觉编码
大规模预训练表征CLIP、MAE、DINOv2先学通用视觉特征，再迁移到分类

这也能和前面的网络结构系列对应起来：CNN 系列关注“视觉编码器怎么设计”；放到图像分类任务里看，视觉编码器已经从 CNN backbone 演进到了预训练基础模型。

但无论编码器从哪里来，图像分类这个算法抽象仍然没有变：

输入图像 → 输出类别概率 → 用真实标签监督训练

5. 图像分类的延伸

5.1 和其他 CV 任务的关系

图像分类不是 CV 的全部，但它是很多任务的起点。

  • 图像分类：只判断整张图是什么。
  • 语义分割：把分类从整张图扩展到每个像素。
  • 目标检测：先判断“这里是不是物体”，再判断“它是什么类别”，还要回归边框。
  • 实例分割：还要区分同一类别里的不同个体。

所以图像分类是一个很好的起点。它先把最基础的问题讲清楚：

给一个输入，输出它属于每个类别的概率。

理解了这件事，后面再看语义分割、目标检测、实例分割，就不是从零开始，而是在看“分类任务又叠加了什么新要求”。

5.2 工程生态：timm 让 backbone 变成可选件

工业界和研究者现在常用的，往往不是某一篇论文的单独代码，而是模型库。

timm / pytorch-image-models 就是典型例子。它收集了大量 PyTorch 图像编码器和 backbone，包括 ResNet、EfficientNet、ViT、Swin、ConvNeXt、MobileNet 等，是现在很常用的图像模型库。

它的价值不是提出一个新结构，而是把很多经典结构整理成统一接口。以前读一篇论文，可能要单独找作者代码、对齐预处理方式、加载权重；用了 timm 之后，很多模型可以用同一种方式创建：

import timm

model = timm.create_model("resnet50", pretrained=True, num_classes=10)

这背后其实反映了图像分类生态的成熟：模型结构越来越多，工程上更需要一个稳定的“模型货架”。研究者可以快速比较 backbone，工业界也可以更方便地挑选适合部署的模型。

实际开发中，很多时候不会从零实现 ResNet、ViT 或 Swin，而是直接从模型库里选一个 backbone：

选择 backbone → 加分类头 → fine-tune / linear probe
