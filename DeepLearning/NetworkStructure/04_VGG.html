VGG：小卷积核堆叠的极致

约 2320 字大约 8 分钟

神经网络CNNVGG

1. AlexNet 之后的问题

2012 年 AlexNet 以 top-5 错误率 15.3% 横扫 ImageNet（第二名 26.2%），证明了"更大更深"确实是方向。但当时的研究者面对一个具体的问题：卷积核到底该用多大？

AlexNet 用了三种核：11×11（Conv1）、5×5（Conv2）、3×3（Conv3~5）。没人能说清这些尺寸是设计出来的还是试出来的。如果选 7×7 会不会更好？11×11 是不是太大了？有没有一个通用的原则？

2014 年，Oxford 的 Visual Geometry Group（VGG）做了一个极端的选择：把所有卷积核统一成最小的 3×3，然后靠堆叠层数来扩大感受野。结果是一个极其规律的网络，以牺牲参数量为代价，证明了深度本身的价值。VGG 以 138M 参数拿下了 ILSVRC-2014 定位任务冠军、分类任务亚军（冠军是 GoogLeNet）。

一句话记住 VGG：把核做小、把网络做深、把结构做规律。

2. VGG 的选择：全 3×3

2.1 为什么是 3×3

3×3 是能捕获"左、中、右 + 上、中、下"的最小尺寸。1×1 只看自己，没有空间信息。3×3 刚好让卷积核"看见"邻居——这是 CNN 能提取局部特征的最小单元。

VGG 的核心洞察：堆叠多个小核，等效于一个大核，但参数更少、非线性更强。

堆叠等效大核参数量（输入=C, 输出=C）节省
两层 3×35×52×9C2=18C22 \times 9C^2 = 18C^22×9C2=18C2 vs 25C225C^225C228%
三层 3×37×73×9C2=27C23 \times 9C^2 = 27C^23×9C2=27C2 vs 49C249C^249C245%

从计算结果看：三层 3×3 比一层 7×7 省了近一半参数，还多了三层 ReLU 非线性。每一层非线性都在增加决策边界的表达能力。

2.2 设计哲学

VGG 的选择本质上是一种"拆解"思维：把一个大核的一次计算，拆成多个小核的串联计算。每一层都是特征提取器，而不是一个大核"一步到位"。

你想一下，7×7 核在输入上滑一次，看到 49 个像素，然后直接输出一个值。三层 3×3 核看到同样 49 个像素，但中间经过了两层非线性变换 --> 模型的判别能力更强了。代价是多了一层计算，但在 2014 年 GPU 已经可以承受。

设计哲学：用一个 7×7 核，网络只能做一次决策；用三个 3×3 核，网络可以做三次决策（激活函数）。

3. VGG 的结构拆解

VGG 的结构极其规律。规律到什么程度？读一遍论文的配置表，你就能在脑子里默写出整个网络。这在新兴的深度学习领域是一种奢侈（AlexNet 的结构你得来回翻几遍才能记住）。

3.1 五段式设计

VGG16 把 13 层卷积分成 5 个 stage，每个 stage 包含 2~3 层 3×3 Conv，末尾接一个 2×2 MaxPool（stride 2）。通道数的变化规律是：每池化一次通道翻倍。

Stage卷积层数通道数输出尺寸
1Conv3-64 ×264224×224 → 112×112
2Conv3-128 ×2128112×112 → 56×56
3Conv3-256 ×325656×56 → 28×28
4Conv3-512 ×351228×28 → 14×14
5Conv3-512 ×351214×14 → 7×7

为什么通道到 512 就停了？因为越到深层，空间尺寸越小，但每层的激活图（activation map）大小是 空间尺寸×空间尺寸×通道数。如果 Stage 5 把通道翻倍到 1024，那层激活图就是 7×7×1024 = 50K 个激活值，这在 2014 年的一张显卡上扛不住。停在 512 是性能与精度的平衡点。

3.2 VGG16 vs VGG19

VGG19 就是在 Stage 3/4/5 各多叠一层 Conv：

  • VGG16：[64,64, M, 128,128, M, 256,256,256, M, 512,512,512, M, 512,512,512, M, FC]
  • VGG19：[64,64, M, 128,128, M, 256,256,256,256, M, 512,512,512,512, M, 512,512,512,512, M, FC]

VGG19 只比 VGG16 多了 3 层 conv，参数从 138M 涨到 144M，但精度的提升非常有限（不到 1%）。所以后人几乎只用 VGG16，多那三层不值得。

3.3 参数魔咒：全连接的黑洞

VGG16 有 ~138M 参数，分布极不均衡：

  • 13 层卷积合计：约 14.7M 参数（10.6%）
  • FC1（25088 → 4096）：102.7M 参数（74.4%）
  • FC2（4096 → 4096）：16.8M 参数（12.2%）
  • FC3（4096 → 1000）：4.1M 参数（3.0%）
  • 三个 FC 合计：123.6M 参数（89.6%）

FC1 一个层比 AlexNet 整个网络（62M）还多 40M 参数。VGG 虽然把卷积层做得规律又高效，但全连接层继承了 AlexNet 的设计，成了参数黑洞。

这也是为什么后来的 MobileNet 和 ResNet 放弃全连接、改用全局平均池化（GAP），省掉的不只是参数，还有过拟合的风险。

4. 信息流动

4.1 VGG16 完整结构

输入 224×224×3
│
├─ Stage 1: [Conv3-64] × 2 + ReLU
│  → MaxPool 2×2, s2          → 112×112×64
│
├─ Stage 2: [Conv3-128] × 2 + ReLU
│  → MaxPool 2×2, s2          → 56×56×128
│
├─ Stage 3: [Conv3-256] × 3 + ReLU
│  → MaxPool 2×2, s2          → 28×28×256
│
├─ Stage 4: [Conv3-512] × 3 + ReLU
│  → MaxPool 2×2, s2          → 14×14×512
│
├─ Stage 5: [Conv3-512] × 3 + ReLU
│  → MaxPool 2×2, s2          → 7×7×512
│
├─ Flatten: 25088
├─ FC1: 25088 → 4096 + ReLU + Dropout
├─ FC2: 4096 → 4096 + ReLU + Dropout
└─ FC3: 4096 → 1000 (Softmax)

4.2 PyTorch 实现

PyTorch 的实现简洁到几乎和配置表长得一样：

import torch.nn as nn

# VGG16 配置表
vgg16_config = [64, 64, 'M',
                128, 128, 'M',
                256, 256, 256, 'M',
                512, 512, 512, 'M',
                512, 512, 512, 'M']

def make_layers(cfg):
    layers = []
    in_channels = 3
    for v in cfg:
        if v == 'M':
            layers.append(nn.MaxPool2d(2, stride=2))
        else:
            layers.append(nn.Conv2d(in_channels, v, 3, padding=1))
            layers.append(nn.ReLU(inplace=True))
            in_channels = v
    return nn.Sequential(*layers)

model = nn.Sequential(
    make_layers(vgg16_config),
    nn.Flatten(),
    nn.Linear(25088, 4096),
    nn.ReLU(inplace=True),
    nn.Dropout(0.5),
    nn.Linear(4096, 4096),
    nn.ReLU(inplace=True),
    nn.Dropout(0.5),
    nn.Linear(4096, 1000),
)

这里用到了一个技巧：VGG 的配置表用数字表示卷积层输出通道数，用 'M' 表示 MaxPool。整个网络的 13 层卷积就用一个循环搭出来了，不需要逐层手写。这个模式在后来被很多网络沿用。

5. 知识扩展

5.1 感受野的递推计算

感受野（Receptive Field）指的是输出特征图上的一个点对应到输入图像上有多大区域。VGG 的堆叠设计让感受野的计算变成简单的递推：

RFout=RFin+(kernel_size−1)×stride_accumulatedRF_{out} = RF_{in} + (kernel\_size - 1) \times stride\_accumulated RFout​=RFin​+(kernel_size−1)×stride_accumulated

从输入层开始（RF=1RF=1RF=1），逐层计算：

  • 一层 3×3 Conv（stride=1）：RF=1+(3−1)×1=3RF = 1 + (3-1) \times 1 = 3RF=1+(3−1)×1=3
  • 两层 3×3 Conv 堆叠：RF=3+(3−1)×1=5RF = 3 + (3-1) \times 1 = 5RF=3+(3−1)×1=5
  • 三层 3×3 Conv 堆叠：RF=5+(3−1)×1=7RF = 5 + (3-1) \times 1 = 7RF=5+(3−1)×1=7

但注意 VGG 中间有 MaxPool（stride=2），池化会改变累积步长。一旦经过池化，后续层的 stride_accumulated 要乘以 2：

  • Stage 2 第一层 Conv（3×3）：RF=5+(3−1)×2=9RF = 5 + (3-1) \times 2 = 9RF=5+(3−1)×2=9
  • Stage 2 第二层 Conv（3×3）：RF=9+(3−1)×2=13RF = 9 + (3-1) \times 2 = 13RF=9+(3−1)×2=13
  • Stage 2 第三层 Conv（3×3）：RF=13+(3−1)×2=17RF = 13 + (3-1) \times 2 = 17RF=13+(3−1)×2=17

每次经过一个 stride=2 的池化，accumulated stride 就翻倍。Stage 5 的 accumulated stride 已经是 24=162^4 = 1624=16，所以整体感受野是按指数增长的，而不是线性。

VGG 最后 Stage 5 输出（7×7×512）的每个点，对应到原始输入的感受野是 212×212（几乎覆盖整张 224×224 图像）。

5.2 ILSVRC-2014 的格局：VGG 与 GoogLeNet

ILSVRC（ImageNet Large Scale Visual Recognition Challenge） 是 2010 年开始的年度视觉竞赛，AlexNet 在 2012 年夺冠后成了 AI 界的"超级碗"。2014 年的格局非常有趣：两个截然不同的思路，同时达到世界顶级水准。

VGG（Oxford）选择了"纯小核堆叠"：全部用 3×3 Conv，靠堆深度（16~19 层）扩大感受野。结构极其规律，138M 参数，分类任务 top-5 错误率 7.3%。

GoogLeNet（Google，也叫 Inception v1）选择了"多尺度并联"：在同一层里用 1×1、3×3、5×5 的卷积核并行计算，然后拼接输出。每个 Inception 模块内部还用了 1×1 Conv 做降维，控制参数量。最终 GoogLeNet 只有 ~6.8M 参数（VGG 的 1/20），top-5 错误率 6.7%，拿了分类冠军。VGG 以 7.3% 紧随其后，但拿了定位任务的冠军。

设计哲学的对照：VGG 在一条路上堆到最深，GoogLeNet 在一个点上看到最宽。VGG 靠深度换表达能力，GoogLeNet 靠宽度换多尺度信息。

GoogLeNet 的参数效率远高于 VGG，但 VGG 的简单和规律让它成为了迁移学习时代的首选。两个网络的共同启示是：2014 年的 GPU 已经可以支撑"足够复杂"的结构设计，接下来的问题不再是"能不能做深"，而是"怎么做深才不退化"——这个问题最终由 ResNet 在 2015 年回答。

5.3 VGG 在今天

VGG 在 2014 年之后很快被超越，但它留下了两个遗产：

  1. 迁移学习的黄金 backbone：VGG16 的结构极其规律，改起来非常方便。在 ResNet 出现之前，几乎所有视觉任务都是用预训练的 VGG16 做 finetune。甚至在 2020 年左右的很多论文里，VGG16 仍然是 baseline 之一。

  2. "结构规律"本身就是贡献：VGG 之前的网络偏经验主义，VGG 之后的研究者开始系统地思考架构设计原则——为什么 3×3 比 5×5 好？为什么深度有意义？这些思考直接催生了 ResNet 的残差连接。

VGG 在今天已经很少直接作为主干网络使用（MobileNet 更轻量、ResNet 更深），但每一个学 CNN 的人都会先看一遍 VGG，因为它是"网络可以做得这么规整"的第一个证明。
