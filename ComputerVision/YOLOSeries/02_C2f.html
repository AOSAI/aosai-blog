C2f：分支、逐级变换与拼接

约 3345 字大约 11 分钟

YOLOYOLOv8网络结构

1. C2f 为什么出现

1.1 相似梯度信息的瓶颈

2019 年的 跨阶段部分网络（Cross Stage Partial Network，CSPNet） 论文以 密集连接网络（Densely Connected Convolutional Networks，DenseNet） 为例：早期特征会进入多个后续层。这使后续层要处理的通道越来越多，增加计算和访存；训练时，不同层的参数更新还可能利用相近的梯度信息，学到相近的内容，新增特征的互补性因此可能降低。图 1 展示了早期特征怎样被多层接收。CSPNet 论文第 3.1 节

1.2 从 CSP 到 YOLOv5 的 C3

CSPNet 的做法是把一个阶段的特征分成两路：一路进入计算较重的模块，另一路绕过它，最后再汇合。为什么只让部分通道进入重模块？旁路的信息没有丢弃，出口仍能同时利用旁路与加工后的特征；因此可以减少重模块处理的通道数，降低计算和访存，同时保留两路信息供后续使用。这是在计算成本与特征表达之间做的取舍，并不是说旁路的通道没有价值。

训练时，旁路不经过重模块，来自旁路的梯度就不会更新重模块的权重；重模块只从处理路收到梯度。CSPNet 论文希望借此减少不同层对相近梯度信息的重复利用，让各层学到的特征更互补。这是改善训练中信息利用方式的目标；计算节省则直接来自重模块处理的通道变少。推理时不计算梯度。CSPNet 论文第 1、3.1 节

YOLOv5 的 C3 模块（CSP Bottleneck with 3 Convolutions） 沿用了分路思路：处理路连续经过多个 瓶颈模块（Bottleneck），最后与旁路汇合。但出口卷积只直接接收旁路和处理链的最终结果；链中较早的结果虽然参与后续计算，却不能直接交给出口卷积。Ultralytics 的架构说明

1.3 YOLOv8 的 C2f 改了什么

2023 年发布的 YOLOv8 改用 跨阶段部分连接瓶颈模块的快速实现（Faster Implementation of CSP Bottleneck with 2 Convolutions，C2f）。C3 为两路分别做入口卷积，C2f 则用一次入口卷积生成两份特征；外层连同出口卷积，共有两个卷积块。它把两份起始特征 a、b 都留到出口：a 绕过 Bottleneck 链，b 原样保留一份，同时作为这条链的输入；链中每个 Bottleneck 的结果也留下来，一起交给出口卷积。这样，出口能直接组合经过不同次数处理的特征。从结构看，C2f 补上了 C3 出口不能直接接收中间结果的缺口。Ultralytics 的 C3、C2f 对照

C2f 接收一组 特征图（Feature Map），输出另一组特征图。设输入形状为 B×C₁×H×W，输出为 B×C₂×H×W：它可以调整 通道数（Number of Channels），但模块里的卷积都不缩小高和宽。这里的 B 是 批次大小（Batch Size），H×W 是每个通道的空间尺寸。

入口卷积生成新通道后，chunk 总是按固定位置分成前一半和后一半；它不会随机挑通道。分路使 Bottleneck 链只处理其中一份，但出口卷积还要处理所有拼接结果，所以仅凭“分成两路”不能断言 C2f 消除了重复梯度，或整个模块的计算量一定比 C3 小。图 2 以内部串联两个 Bottleneck 为例。Ultralytics v8.3.0 的 C2f 源码

2. 一组特征图怎样通过 C2f

先认清两个配置参数：

  • e 是内部通道比例。源码用目标输出通道数 C2C_2C2​ 算出每路的通道数 c=⌊eC2⌋c=\lfloor eC_2\rfloorc=⌊eC2​⌋。它不直接把输入通道对半分；入口卷积先生成 2c 个新通道，后面的 chunk 才把它们平分成两路。
  • n 是一个 C2f 内串联的 Bottleneck 个数。n=2 表示特征依次通过两个 Bottleneck，不表示整个网络只有两个，也不表示只有两层卷积。C2f 源码

沿着图 2 走一遍具体数据：输入 X 是 1×128×80×80，目标输出通道数 C2=128C_2=128C2​=128，取 e=0.5、n=2。这些数字只用于看清每一步的形状。

2.1 输入经过入口卷积

入口的 1×1 卷积（1×1 Convolution） cv1 接收 X。先把它两端的通道数分别算清楚：

  1. 算输出通道数：目标输出通道数是 C2=128C_2=128C2​=128，内部比例是 e=0.5e=0.5e=0.5，所以每路的通道数 c=⌊eC2⌋=64c=\lfloor eC_2\rfloor=64c=⌊eC2​⌋=64。cv1 要生成两路，共 2c=1282c=1282c=128 个新通道。
  2. 读输入通道数：输入 X 的形状已给定为 1×128×80×80，其中第二个数就是输入通道数 C1=128C_1=128C1​=128。它不是由 C2C_2C2​ 和 eee 反推出来的。因此本例的 cv1 是 128 → 128，输出形状仍为 1×128×80×80。

本例输入和目标输出恰好都是 128 通道，所以 c=64c=64c=64 也等于输入的一半；若两者通道数不同，就未必如此。cv1 前后的通道数虽然同为 128，输出 cv1(X) 仍是卷积新算出的特征。C2f 源码

2.2 将入口特征分成两份

chunk(2, dim=1) 沿通道维把 cv1(X) 切开：前 64 个通道是 a，后 64 个通道是 b。两份的形状各为 1×64×80×80。它们不是同一份特征的两个副本：cv1 为前后两组输出通道分别计算数值，chunk 只按固定位置切分，不随机选通道。a 留到出口，b 留下一份，同时送入第一个 Bottleneck。C2f 源码

2.3 b 依次通过两个 Bottleneck

第一个 Bottleneck 读取 b，得到 z₁；第二个读取刚算出的 z₁，得到 z₂：

z1=B1(b),z2=B2(z1).z_1=B_1(b),\qquad z_2=B_2(z_1). z1​=B1​(b),z2​=B2​(z1​).

这里的 Bottleneck 是 C2f 内部的卷积子模块，不是整个 C2f。图 2 中的 B₁ 和 B₂ 都依次执行两个保持高宽的 3×3 卷积块：64 通道 → 64 通道 → 64 通道，不会再次把通道对半分。它们的结构相同、权重各自独立；权重在训练中更新，推理时固定。C2f 源码；Bottleneck 源码

按图 2 的 n=2 计算，整个 C2f 有入口 cv1 一块 + 两个 Bottleneck 各两块 + 出口 cv2 一块 = 6 个卷积块；只有 n=1 时才是 4 个。它们并非排成一条六层直链：a 绕过两个 Bottleneck，b、z₁、z₂ 在出口一起拼接。

shortcut=False 时，一个 Bottleneck 的输出就是第二个卷积块的结果；shortcut=True 且输入、输出通道相同时，还会把该 Bottleneck 的输入与卷积结果相加。这是建模时选定的连接方式，不是对每张图临时切换。本例取 False，因此 b、z₁、z₂ 形状都为 1×64×80×80；z₁ 和 z₂ 分别经过一轮、两轮处理，b 和 z₁ 也会保留到出口。第 4.1 节会把这两个卷积块写成代码。

2.4 拼接四份特征，再经过出口卷积

现在按 a、b、z₁、z₂ 的顺序做按通道拼接（Concatenation，Concat）。每份有 64 个通道，拼接后是 1×256×80×80：高宽不变，只把四组通道排在一起，没有逐元素相加。出口卷积 cv2 再把 256 个通道组合成目标的 128 个通道，得到 Y=1×128×80×80：

Y=cv2⁡ ⁣(Concat⁡C(a,b,z1,z2)).Y=\operatorname{cv2}\!\left(\operatorname{Concat}_{C}(a,b,z_1,z_2)\right). Y=cv2(ConcatC​(a,b,z1​,z2​)).

出口 1×1 卷积在每个空间位置混合这些通道。换成任意 n，拼接前会留下 a、b 和 n 个 Bottleneck 的结果，共 n+2 份、(n+2)c 个通道；整条路径的高宽始终为 H×W。C2f 源码

3. C2f 相比 C3 改了什么，用在 YOLOv8 哪里

3.1 先看 C3 怎样分路与汇合

第 1.2 节提到的 C3 是 YOLOv5 使用的跨阶段分路模块。它用两次独立的入口 1×1 卷积处理同一个输入：一路经过连续的 Bottleneck，另一路绕过这条处理链；最后只把旁路结果和处理链的最终结果拼接，再经过出口 1×1 卷积。名字中的“3”指这三个外层卷积块，不包含 Bottleneck 内部的卷积。C3 源码

例如链中有两个 Bottleneck：处理路先得到 u=cv1(X)，再依次得到 B₁(u)、B₂(B₁(u))；旁路得到 v=cv2(X)。出口 cv3 只读取 v 和 B₂(B₁(u)) 的拼接结果。u 和第一步结果参与了计算，但没有直接送到出口。这就是下面要与 C2f 对照的地方。

3.2 C2f 改变了哪两处连接

C2f 只用一次入口 cv1(X)，再沿通道切出 a、b；出口除了旁路 a 和处理链终点 z₂，还直接接收链的起点 b 与第一步结果 z₁。图 3 的虚线框表示“算过但没直接送到出口”，不是“这一层没有执行”。图中只比较哪些结果进入出口卷积：C3 拼接 2c 个通道，C2f 在 n=2 时拼接 4c 个通道；出口卷积再各自组合这些输入。C3 与 C2f 源码

3.3 YOLOv8 的八处 C2f 在哪里工作

在 Ultralytics v8.3.0 的 YOLOv8 检测配置中，骨干网络（Backbone）有四处 C2f，分别处理逐级下采样后的特征；检测头前的颈部网络（Neck）也有四处 C2f，分别处理上采样或下采样后与另一层拼接的特征。配置文件把后四处列在 head 段，但它们都在最终的 Detect 层之前，执行多尺度融合。

这里说的是八个放置位置，每个位置内部的 Bottleneck 个数 n 可以不同；第 2 节的 n=2 只用于演示。骨干中的四处配置了 shortcut=True，颈部的四处没有传这个参数，使用 C2f 默认的 False。因此，图 2 的分路、逐级处理、拼接流程可以复用，块内是否加上输入则由配置决定。C2f 源码

图 2 的 cv1、cv2，以及 B₁、B₂ 内部的每个卷积块，采用的都是 Ultralytics Conv：Conv2d → BN → SiLU。其中，批归一化（Batch Normalization，BN） 在训练时按批次规范化卷积输出，帮助后续层在较稳定的数值尺度上学习；SiLU 激活函数（Sigmoid Linear Unit，SiLU） 对规范化后的数值做非线性变换。它们包含在图 2 的卷积块里，不在 chunk 或 Concat 上额外执行。Ultralytics Conv 源码；BN 原论文

C2f 自身在同一张 H×W 网格上工作，不负责把高宽减半或放大：骨干中的下采样由相邻的步长为 2 的卷积完成，融合路径中的尺寸调整由相邻的上采样或下采样操作完成。八处 C2f 都不直接输出检测框；完整路径见 YOLOv8 总览。

4. 用原生 PyTorch 写出 C2f

下面只用 PyTorch 实现本篇讨论的配置：普通卷积、3×3 Bottleneck、可选的块内相加，再按图 2 拼接。Conv 块写全 Conv2d → BN → SiLU；C2f 的通道计算和特征流对应 Ultralytics v8.3.0 源码。两个代码块按顺序放在同一个 Python 文件中即可运行。

4.1 先实现 Bottleneck

import torch
from torch import nn


class ConvBNAct(nn.Sequential):
    def __init__(self, c1, c2, k):
        super().__init__(
            nn.Conv2d(c1, c2, kernel_size=k, stride=1,
                      padding=k // 2, bias=False),
            nn.BatchNorm2d(c2),
            nn.SiLU(),
        )


class Bottleneck(nn.Module):
    def __init__(self, channels, shortcut=False):
        super().__init__()
        self.cv1 = ConvBNAct(channels, channels, 3)
        self.cv2 = ConvBNAct(channels, channels, 3)
        self.shortcut = shortcut

    def forward(self, x):
        result = self.cv2(self.cv1(x))
        return x + result if self.shortcut else result

两个 3×3 卷积都用 padding=1、stride=1，所以输入和输出同为 c×H×W。shortcut=True 时才执行 x + result；图 2 的教学例子选 False。这里固定了 C2f 使用的等通道、普通卷积版本，省略官方 Bottleneck 的其他可选参数。Bottleneck 源码

4.2 再实现 C2f 并检查每一步

class C2f(nn.Module):
    def __init__(self, c1, c2, n=1, e=0.5, shortcut=False):
        super().__init__()
        self.c = int(c2 * e)
        self.cv1 = ConvBNAct(c1, 2 * self.c, 1)
        self.blocks = nn.ModuleList(
            Bottleneck(self.c, shortcut) for _ in range(n)
        )
        self.cv2 = ConvBNAct((n + 2) * self.c, c2, 1)

    def forward(self, x):
        parts = list(self.cv1(x).chunk(2, dim=1))  # a, b
        for block in self.blocks:
            parts.append(block(parts[-1]))       # z1, z2, ...
        return self.cv2(torch.cat(parts, dim=1))


module = C2f(c1=128, c2=128, n=2, e=0.5, shortcut=False).eval()
x = torch.randn(1, 128, 80, 80)

with torch.no_grad():
    entry = module.cv1(x)
    a, b = entry.chunk(2, dim=1)
    z1 = module.blocks[0](b)
    z2 = module.blocks[1](z1)
    joined = torch.cat((a, b, z1, z2), dim=1)
    y = module(x)
    manual = module.cv2(joined)

assert torch.allclose(y, manual)
for name, value in (("a", a), ("b", b), ("z1", z1),
                    ("z2", z2), ("Concat", joined), ("Y", y)):
    print(name, tuple(value.shape))

a、b、z1、z2 各为 1×64×80×80，Concat 为 1×256×80×80，Y 为 1×128×80×80。最后的断言还检查手动沿图 2 计算与 C2f.forward() 得到相同结果；随机输入和未经训练的权重不能说明检测效果。

把构造参数改成 shortcut=True，第 4.1 节的 x + result 就会在每个 Bottleneck 内执行；C2f 外层的分路和拼接顺序不变。
