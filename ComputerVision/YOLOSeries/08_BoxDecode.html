预测框解码

YOLOYOLOv8预测框解码

1. 一个预测位置怎样变成候选框

1.1 先看解码前后

YOLOv8 先把输入图像变成几张较小的特征图（Feature Map），每张特征图有许多网格位置，每个位置包含一组数值。图 1 只看其中一个网格位置：

  1. 左侧，解码前：模型分别给“左、上、右、下”四个方向的距离档位打分，每个方向有 16 个原始分数（Logits）。每个小格代表一个分数，不是图像像素；4×16 个数也不是 64 个框。
  2. 中间，解码中：预测框解码（Bounding Box Decoding）把每组分数变成一个距离。紫点是网格参考点（Anchor Point），四支箭头表示它到四条框边的距离，单位是网格格数。
  3. 右侧，解码后：根据参考点和四个距离确定框边，再换算成图像像素坐标，得到珊瑚色的候选框（Candidate Box）。类别分数不参与框坐标的计算。

1.2 中间和右侧为什么使用不同单位

假设模型接收一张 640×640 的图像，它的一张 P4 特征图有 40×40 个网格位置。

图 1 只跟踪其中行索引 7、列索引 10 的位置，索引从 0 开始；该格中心就是图中的参考点 A=(10.5,7.5)A=(10.5,7.5)A=(10.5,7.5)。

中间四支箭头分别长 2、1.5、3、2.5 格。这些距离以网格格数计，不能直接当成图像像素；该层的步长（Stride）为 640÷40=16，所以网格上的 1 格对应输入图像的 16 像素。

右侧的 (136,96) 与 (216,160) 是框的两个角，单位已经换成模型接收的这张 640×640 图像上的像素。若原照片在送入模型前经过缩放和补边，要把框画回原照片，还需要按缩放比例和补边量反向换算。

2. 每组 16 个数怎样变成一个距离

2.1 从原始分数到 16 个权重

2.2 DFL 解码模块与 DFLoss 训练损失

图 1 的第一步是解码：推理源码中的 DFL 模块接收四组、每组 16 个原始分数，对每组做 Softmax 和加权平均，输出左、上、右、下四个距离。用来加权的档位编号 0～15 是固定数值，不参与训练。第二步再用参考点和四个距离确定框边，并按步长换算成图像像素；最终得到的是候选框。DFL 模块源码、dist2bbox 源码

训练时还有分布焦点损失（Distribution Focal Loss），本文按源码类名叫它 DFLoss。它接收预测的 16 档原始分数和标注对应的距离，算出损失值，用于更新网络参数。DFL 模块与 DFLoss 使用同一套距离档位表示，但不是同一个操作：前者输出距离，后者输出训练误差。推理模块虽然叫 DFL，本身却不计算损失。DFLoss 源码

3. 四个距离怎样组成一个框

3.1 先确定参考点

本例的 P4 特征图有 40×40 个网格位置。用 jjj 表示行、iii 表示列，两者都从 0 数到 39；每一格都有参考点。文章只选第 7 行、第 10 列来演示，因此 j=7,i=10j=7,i=10j=7,i=10。这两个数是示例位置的索引，不是模型根据人所在的位置算出来的。YOLOv8 把参考点固定在每格中心，所以这一格的参考点为 (ax,ay)=(i+0.5, j+0.5)=(10.5,7.5)(a_x,a_y)=(i+0.5,\,j+0.5)=(10.5,7.5)(ax​,ay​)=(i+0.5,j+0.5)=(10.5,7.5)，单位是网格格数。make_anchors 源码

这一格在本例 YOLOv8n 的 P4 上还有 128 个通道值：每个通道在第 7 行、第 10 列各有一个数。它们是 128 个特征数，不会先合成一个数，也不是 128 个参考点。这些数由前面的网络算出；检测头的卷积还会利用附近位置的特征，最终在这一格输出四组距离分数和类别分数。YOLOv8 v8.3.0 网络配置、Detect 源码

参考点按网格排列，不会为了某个人特意移动到人体中心。它可以落在人框内偏上、偏左等位置；该位置仍能预测到人框四边的距离，得到完整的候选框。训练时，人框内符合分配条件的多个位置都可能学习预测这个人。参考点只规定从哪里量距离，不是预设了宽高的锚框。select_candidates_in_gts 源码

3.2 从参考点向四边量距离

图像坐标中，xxx 向右增大，yyy 向下增大。设左、上、右、下四个解码距离分别为 dl,dt,dr,dbd_l,d_t,d_r,d_bdl​,dt​,dr​,db​，框的左上角是 (x1,y1)(x_1,y_1)(x1​,y1​)，右下角是 (x2,y2)(x_2,y_2)(x2​,y2​)。从参考点向左、上做减法，向右、下做加法：

(x1,y1)=(ax−dl, ay−dt),(x2,y2)=(ax+dr, ay+db).(x_1,y_1)=(a_x-d_l,\ a_y-d_t), \qquad (x_2,y_2)=(a_x+d_r,\ a_y+d_b). (x1​,y1​)=(ax​−dl​, ay​−dt​),(x2​,y2​)=(ax​+dr​, ay​+db​).

沿用 (ax,ay)=(10.5,7.5)(a_x,a_y)=(10.5,7.5)(ax​,ay​)=(10.5,7.5)，假设四个距离是 (dl,dt,dr,db)=(2,1.5,3,2.5)(d_l,d_t,d_r,d_b)=(2,1.5,3,2.5)(dl​,dt​,dr​,db​)=(2,1.5,3,2.5) 格，就得到网格坐标下的框 (x1,y1,x2,y2)=(8.5,6,13.5,10)(x_1,y_1,x_2,y_2)=(8.5,6,13.5,10)(x1​,y1​,x2​,y2​)=(8.5,6,13.5,10)。图 3 的紫色点是参考点，珊瑚色线是框的四条边；四个距离各自决定一条边，不要求左右或上下相等。

3.3 乘上步长，换成图像像素

网格上的 1 格对应预处理后输入图像的 16 像素，所以将四个边界坐标都乘以步长 16：

(x1,y1,x2,y2)px=16(8.5,6,13.5,10)=(136,96,216,160).(x_1,y_1,x_2,y_2)_{\mathrm{px}} =16(8.5,6,13.5,10) =(136,96,216,160). (x1​,y1​,x2​,y2​)px​=16(8.5,6,13.5,10)=(136,96,216,160).

4. 训练与推理分别怎样使用解码

4.1 两边都要解码，但接下来的用途不同

两边都要解码，四个距离到框边界的数学关系相同。训练时，检测头先返回原始预测；损失计算模块再把框分数解码为网格坐标下的两角框，用于正样本分配和框损失。推理时，Detect 解码并乘步长，输出预处理后图像像素坐标下的中心点与宽高，供后续筛选。v8.3.0 训练损失源码、推理源码

4.2 8400 个候选框怎样筛选

解码只回答“每个位置给出什么框”。以本例 640×640 输入为例，三层共有 8400 个候选位置；推理时按下面的顺序筛选：

  1. 按类别分数过滤：每个位置还有各类别的分数。若最高类别分数低于阈值，就丢弃该位置的候选框，主要排除没有目标的位置。
  2. 用 NMS 去重：剩余位置可能给同一个目标画出多个高度重叠的框。非极大值抑制（Non-Maximum Suppression，NMS）保留分数较高的框，抑制重复框。

所以 NMS 处理的是通过分数筛选后仍然重复的框，不是单独承担 8400 个候选框的全部筛选。v8.3.0 推理筛选源码

训练时哪些位置负责某个目标，由正样本分配决定；推理筛选的细节见 NMS。把保留下来的框从补边图映射回原图，是 LetterBox 的逆向坐标处理。

4.3 用 PyTorch 解码整张预测图

本例的 P4 特征图是 B×128×40×40，经过检测头的框分支后变成 B×64×40×40：64=4×16 是四个方向各 16 个原始分数，高、宽仍是 40×40。因此，分数图第 j 行、第 i 列的 64 个分数，就对应同一位置 (i+0.5,j+0.5)(i+0.5,j+0.5)(i+0.5,j+0.5) 的参考点；i、j 由分数图的高、宽生成，不需要逐个手填。Detect 源码、make_anchors 源码

下面的函数一次解码这张图的所有位置。为了对照图 3，它返回像素坐标下的两角框 xyxy；实际 Detect 推理输出还会把框换成中心点与宽高。代码用手工分数构造第 7 行、第 10 列的例子，其余位置只是占位，不代表真实预测。

import math

import torch

def decode_boxes(box_logits: torch.Tensor, stride: int) -> torch.Tensor:
    """[B, 64, H, W] 的框分数 → [B, H, W, 4] 的像素坐标 xyxy。"""
    batch, channels, height, width = box_logits.shape
    if channels != 4 * 16:
        raise ValueError("每个位置应有 4×16 个框分数")

    # 保留 H、W：每一格都有四组、每组 16 个分数。
    scores = box_logits.reshape(batch, 4, 16, height, width)
    scores = scores.permute(0, 3, 4, 1, 2)  # [B, H, W, 4, 16]
    bins = torch.arange(16, dtype=box_logits.dtype, device=box_logits.device)
    distances = (scores.softmax(dim=-1) * bins).sum(dim=-1)  # [B, H, W, 4]

    # 根据预测图的 H、W 枚举所有 (行 j, 列 i)，与 scores 的空间位置对齐。
    j, i = torch.meshgrid(
        torch.arange(height, device=box_logits.device),
        torch.arange(width, device=box_logits.device),
        indexing="ij",
    )
    anchors = torch.stack((i, j), dim=-1).to(box_logits.dtype) + 0.5
    top_left = anchors - distances[..., :2]       # 减去左、上距离
    bottom_right = anchors + distances[..., 2:]   # 加上右、下距离
    return torch.cat((top_left, bottom_right), dim=-1) * stride


# 构造一张 P4 框分数图；row、col 仅用于填入并查看示例位置。
row, col = 7, 10
example = torch.full((1, 4, 16, 40, 40), -100.0)
example[0, 0, 2, row, col] = 0.0             # 左：2 格
example[0, 1, :, row, col] = 0.0
example[0, 1, 1, row, col] = math.log(589)   # 上：沿用 2.1 节的分数
example[0, 1, 2, row, col] = math.log(397)
example[0, 2, 3, row, col] = 0.0             # 右：3 格
example[0, 3, 2:4, row, col] = 0.0           # 下：2.5 格

box_logits = example.reshape(1, 64, 40, 40)
boxes = decode_boxes(box_logits, stride=16)
print(boxes.shape)                    # torch.Size([1, 40, 40, 4])
print(boxes[0, row, col].tolist())   # [136.0, 96.0, 216.0, 160.0]

meshgrid 生成整张图的 j、i 索引；scores 与 anchors 都保留相同的 H×W 排列，所以第 j 行、第 i 列的分数只会和这一格的参考点配对。示例中的 row=7、col=10 只是构造与查看这一格，不会作为参数传进解码函数。类别分数过滤和 NMS 不改变这里的框坐标计算。
