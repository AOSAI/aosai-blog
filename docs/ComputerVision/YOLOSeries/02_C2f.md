## **1. C2f 为什么出现**

### **1.1 相似梯度信息的瓶颈**

2019 年的 ==跨阶段部分网络（Cross Stage Partial Network，CSPNet）== 论文以 ==密集连接网络（Densely Connected Convolutional Networks，DenseNet）== 为例：早期特征会进入多个后续层。这使后续层要处理的通道越来越多，增加计算和访存；训练时，不同层的参数更新还可能利用相近的梯度信息，学到相近的内容，新增特征的互补性因此可能降低。图 1 展示了早期特征怎样被多层接收。[CSPNet 论文第 3.1 节](https://arxiv.org/html/1911.11929)

![Fig.1 DenseNet 中早期特征被多层接收，后续层的输入通道逐渐增加](/ComputerVision/YOLOSeries/00_repeated_gradient_sources.png)

### **1.2 从 CSP 到 YOLOv5 的 C3**

CSPNet 的做法是把一个阶段的特征分成两路：一路进入计算较重的模块，另一路绕过它，最后再汇合。**为什么只让部分通道进入重模块？**旁路的信息没有丢弃，出口仍能同时利用旁路与加工后的特征；因此可以减少重模块处理的通道数，降低计算和访存，同时保留两路信息供后续使用。这是在计算成本与特征表达之间做的取舍，并不是说旁路的通道没有价值。

训练时，旁路不经过重模块，来自旁路的梯度就不会更新重模块的权重；重模块只从处理路收到梯度。CSPNet 论文希望借此减少不同层对相近梯度信息的重复利用，让各层学到的特征更互补。这是**改善训练中信息利用方式**的目标；**计算节省**则直接来自重模块处理的通道变少。推理时不计算梯度。[CSPNet 论文第 1、3.1 节](https://arxiv.org/html/1911.11929)

YOLOv5 的 ==C3 模块（CSP Bottleneck with 3 Convolutions）== 沿用了分路思路：处理路连续经过多个 ==瓶颈模块（Bottleneck）==，最后与旁路汇合。但出口卷积只直接接收**旁路和处理链的最终结果**；链中较早的结果虽然参与后续计算，却不能直接交给出口卷积。[Ultralytics 的架构说明](https://docs.ultralytics.com/guides/yolo-architecture#c3-yolov5)

### **1.3 YOLOv8 的 C2f 改了什么**

2023 年发布的 [YOLOv8](https://docs.ultralytics.com/models/yolov8/) 改用 ==跨阶段部分连接瓶颈模块的快速实现（Faster Implementation of CSP Bottleneck with 2 Convolutions，C2f）==。C3 为两路分别做入口卷积，C2f 则用一次入口卷积生成两份特征；外层连同出口卷积，共有两个卷积块。它把两份起始特征 `a、b` 都留到出口：`a` 绕过 Bottleneck 链，`b` 原样保留一份，同时作为这条链的输入；链中**每个 Bottleneck 的结果**也留下来，一起交给出口卷积。这样，出口能直接组合经过不同次数处理的特征。**从结构看，C2f 补上了 C3 出口不能直接接收中间结果的缺口。**[Ultralytics 的 C3、C2f 对照](https://docs.ultralytics.com/guides/yolo-architecture#backbone-blocks-bottleneck-c3-c2f-c3k2)

C2f 接收一组 ==特征图（Feature Map）==，输出另一组特征图。设输入形状为 `B×C₁×H×W`，输出为 `B×C₂×H×W`：它可以调整 ==通道数（Number of Channels）==，但模块里的卷积都不缩小**高和宽**。这里的 `B` 是 ==批次大小（Batch Size）==，`H×W` 是每个通道的空间尺寸。

入口卷积生成新通道后，`chunk` 总是按**固定位置**分成前一半和后一半；它不会随机挑通道。分路使 Bottleneck 链只处理其中一份，但出口卷积还要处理所有拼接结果，所以**仅凭“分成两路”不能断言 C2f 消除了重复梯度，或整个模块的计算量一定比 C3 小**。下面以 `n=2` 为例；`n` 表示内部 Bottleneck 的个数。[Ultralytics v8.3.0 的 C2f 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2531-L2555)

![Fig.2 n=2 时 C2f 从入口卷积、分支、连续 Bottleneck 到拼接输出的数据流](/ComputerVision/YOLOSeries/02_c2f_flow.png)

## **2. 一组特征图怎样通过 C2f**

沿着图 2 走一遍具体数据：输入 `X` 是 `1×128×80×80`，目标输出通道数为 `128`，取 `e=0.5`、`n=2`（两个 Bottleneck）。这些数字只用于看清每一步的形状。

### **2.1 输入经过入口卷积**

先由目标输出通道数 $C_2$ 和比例 $e$ 算出内部通道数 $c=\lfloor eC_2\rfloor=\lfloor0.5\times128\rfloor=64$。入口的 ==1×1 卷积（1×1 Convolution）== `cv1` 接收 `X`，生成 $2c=128$ 个新通道：

$$
z_0=\operatorname{cv1}(X),\qquad
1\times128\times80\times80\ \longrightarrow\ 1\times128\times80\times80.
$$

前后的 `128` 虽然相同，$z_0$ 仍是卷积新算出的特征；每个通道的高宽保持 `80×80`。[C2f 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2540-L2555)

### **2.2 将入口特征分成两份**

`chunk(2, dim=1)` 沿通道维把 $z_0$ 切开：前 `64` 个通道是 `a`，后 `64` 个通道是 `b`。两份的形状各为 `1×64×80×80`。它们**不是同一份特征的两个副本**：`cv1` 为前后两组输出通道分别计算数值，`chunk` 只按固定位置切分，不随机选通道。`a` 留到出口，`b` 留下一份，同时送入第一个 Bottleneck。[C2f 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2540-L2555)

### **2.3 `b` 依次通过两个 Bottleneck**

第一个 Bottleneck 读取 `b`，得到 `z₁`；第二个读取刚算出的 `z₁`，得到 `z₂`：

$$
z_1=B_1(b),\qquad z_2=B_2(z_1).
$$

`b`、`z₁`、`z₂` 都是 `1×64×80×80`。两个 Bottleneck 各自执行两个保持高宽的 `3×3` 卷积块；本例取 `shortcut=False`，块内不与输入相加。**这一步没有覆盖 `b` 或 `z₁`**，三份结果都会在出口使用。[Bottleneck 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2689-L2710)

### **2.4 拼接四份特征，再经过出口卷积**

现在按 `a、b、z₁、z₂` 的顺序做==按通道拼接（Concatenation，Concat）==。每份有 `64` 个通道，拼接后是 `1×256×80×80`：高宽不变，只把四组通道排在一起，**没有逐元素相加**。出口卷积 `cv2` 再把 `256` 个通道组合成目标的 `128` 个通道，得到 `Y=1×128×80×80`：

$$
Y=\operatorname{cv2}\!\left(\operatorname{Concat}_{C}(a,b,z_1,z_2)\right).
$$

出口 `1×1` 卷积在每个空间位置混合这些通道。换成任意 `n`，拼接前会留下 `a、b` 和 `n` 个 Bottleneck 的结果，共 `n+2` 份、`(n+2)c` 个通道；整条路径的高宽始终为 `H×W`。[C2f 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2540-L2555)

## **3. 结构对照与边界**

### **3.1 C3 与 C2f 的差别**

图 3 固定 `n=2`，只比较两者交给出口卷积的内容。C3 的两路分别由入口卷积产生，最后只拼接**旁路和处理链终点**；C2f 先用一次入口卷积生成两路，最后还拼接**处理链起点和每一步的结果**。图中“旁路”都已经过入口卷积，并非原始输入。[C3 与 C2f 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/block.py#L2531-L2590)

![Fig.3 n=2 时 C3 只拼接旁路与最终结果，C2f 还拼接起点和中间结果](/ComputerVision/YOLOSeries/02_c2f_compare.png)

C2f 保留更多结果，也让出口卷积面对更多输入通道：C3 拼接后是 `2c`，C2f 是 `(n+2)c`。因此，**不能仅凭名称中的 Faster 就断言任何输入、设备和实现下都更快**；若要比较速度或检测效果，需要在相同条件下测量。

### **3.2 它负责什么，不负责什么**

C2f 在同一张 `H×W` 网格上组合旁路与不同处理深度的特征。虽然连续 `3×3` 卷积会让后续结果看到更广的邻域，它**不会生成不同空间尺寸的特征金字塔**，也不直接输出检测框。若网络需要下采样，是相邻的步长为 `2` 的卷积在做这件事；C2f 如何放入 YOLOv8 的骨干与特征融合路径，见 [YOLOv8 总览](./01_YOLOv8_Detection.md)。

名称中的“两次卷积”指模块两端的 `cv1`、`cv2`；内部的 Bottleneck 还含卷积。Ultralytics 的 `Conv` 也不只是裸 `Conv2d`，默认还接 ==批归一化（Batch Normalization，BN）== 与 ==SiLU 激活函数（Sigmoid Linear Unit，SiLU）==。[Conv 源码](https://github.com/ultralytics/ultralytics/blob/v8.3.0/ultralytics/nn/modules/conv.py#L910-L931)

## **4. PyTorch 中怎样对应源码并检查**

下面按 Ultralytics v8.3.0 的 `C2f` 接口，拆开同一次前向计算，核对每一步的形状与最终输出。代码需要在安装了兼容版本的容器中运行；`eval()` 让两次前向计算使用相同的批归一化统计量。

```python
import torch
from ultralytics.nn.modules.block import C2f

module = C2f(c1=128, c2=128, n=2, shortcut=False, e=0.5).eval()
x = torch.randn(1, 128, 80, 80)

with torch.no_grad():
    entry = module.cv1(x)
    a, b = entry.chunk(2, dim=1)
    z1 = module.m[0](b)
    z2 = module.m[1](z1)
    joined = torch.cat((a, b, z1, z2), dim=1)
    y = module.cv2(joined)
    same = torch.allclose(y, module(x))

for name, value in (
    ("X", x), ("cv1(X)", entry), ("a", a), ("b", b),
    ("z1", z1), ("z2", z2), ("Concat", joined), ("Y", y),
):
    print(name, tuple(value.shape))
print("与完整 C2f 输出一致：", same)
```

输出形状应与第 2 节逐步得到的形状一致，最后一行应为 `True`。这只验证**数据流与形状**；随机输入和未经训练的权重不能说明模型识别到了什么。
