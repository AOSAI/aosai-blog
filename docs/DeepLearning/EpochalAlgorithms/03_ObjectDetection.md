## 1. 目标检测算法是什么？

图像分类回答的是：`这张图是什么？`

目标检测要同时回答两个问题：

```text
图里有什么？
每个目标在哪里？
```

比如一张街景里有两辆车和一个人。图像分类可能只输出“街景”；目标检测要把三个目标分别找出来，并给出每个目标的类别和位置。

### 1.1 从一张图到多个目标

目标检测的输出不是一个类别，而是一组检测结果：

```text
目标 1：类别 = 车，位置 = 边界框 b1，置信度 = 0.96
目标 2：类别 = 车，位置 = 边界框 b2，置信度 = 0.91
目标 3：类别 = 人，位置 = 边界框 b3，置信度 = 0.94
```

图里有几个目标，最终就应该输出几个结果。如果图里没有目标，最终结果可以是空集合。

![Fig.1 目标检测输出数量不固定的一组类别和边界框](/DeepLearning/EpochalAlgorithms/03_detection_task.png)

目标检测能够区分同一类别中的不同个体。图里有两辆车，就要分别输出两个结果，而不是只说“图里有车”。

### 1.2 一个检测结果包含什么？

一个检测结果通常包含三部分：

- **类别（Class）**：目标是什么，比如车、人、猫。
- **边界框（Bounding Box）**：目标在图像中的位置。
- **置信度（Confidence Score）**：模型对这个结果有多确定。

二维目标检测通常用一个矩形框住目标。最常见的表示方式之一是：

$$
b=(x_{min},y_{min},x_{max},y_{max})
$$

前两个坐标表示矩形左上角，后两个坐标表示矩形右下角。

因此，目标检测算法可以定义成：

> **学习一个函数 $f(x)$，把一张图像 $x$ 映射成一组目标，每个目标包含类别、边界框和置信度。**

$$
f(x)=\{(b_i,c_i,s_i)\}_{i=1}^{N}
$$

- $N$：检测到的目标数量。
- $b_i$：第 $i$ 个目标的边界框。
- $c_i$：第 $i$ 个目标的类别。
- $s_i$：模型对这个结果的置信度。

目标也可以概括成一句话：**类别要正确，位置要准确，同时尽量不漏检、不误检、不重复检测。**

### 1.3 目标检测的稳定算法骨架

不同检测模型的结构差别很大，但它们一直在完成同一套任务：

```text
输入图像
→ 产生一组目标预测
→ 建立预测与真实目标的对应关系
→ 优化目标类别和边界框
→ 输出最终检测结果
```

检测网络本身常被拆成三个部分：

```text
图像 → Backbone → Neck（可选）→ Detection Head → 检测预测
```

- **骨干网络（Backbone）**：把图像变成特征图。
- **特征融合网络（Neck）**：融合不同分辨率的特征，帮助模型同时检测大目标和小目标。
- **检测头（Detection Head）**：根据特征预测类别和边界框。

这是常见的网络结构分工，不是目标检测的任务定义。ResNet、Swin Transformer 可以互换 Backbone，FPN、PAN 可以作为 Neck，检测头也在不断变化，但模型最后仍要输出类别和位置。

### 1.4 怎样训练、预测和评价？

一张训练图像通常带有两部分标注：

- `boxes`：形状为 `(N, 4)`，记录 $N$ 个真实边界框。
- `labels`：形状为 `(N,)`，记录每个边界框的真实类别。

训练时，模型会先产生许多预测，再确定每个预测应该学习哪个真实目标。匹配成功的预测同时学习类别和边界框，没有匹配到目标的预测通常学习背景或“无目标”。

目标检测的核心损失可以写成：

$$
L=L_{cls}+\lambda L_{box}
$$

- $L_{cls}$：分类损失，让目标类别正确。
- $L_{box}$：边界框损失，让预测框靠近真实框。
- $\lambda$：平衡两种损失的权重。

计算完损失后，模型通过反向传播更新参数，再进入下一批、下一个 epoch，形成完整训练闭环。

![Fig.2 目标检测的训练闭环与预测输出](/DeepLearning/EpochalAlgorithms/03_detection_pipeline.png)

预测时不再提供真实框，模型只根据图像输出检测结果。传统检测器一般还要筛掉低置信度和重复的预测；端到端检测器则可以直接输出一组结果。

评价时，类别正确还不够，位置也要正确。通常先用 **[交并比（Intersection over Union，IoU）](../EvaluationMetrics/07_IoU.md)** 衡量预测框和真实框的重叠程度：

$$
IoU=\frac{\text{预测框与真实框的交集面积}}
{\text{预测框与真实框的并集面积}}
$$

在此基础上，再用 [AP](../EvaluationMetrics/11_AP.md) 衡量一个类别在不同置信度阈值下的检测效果，用 [mAP](../EvaluationMetrics/12_mAP.md) 对多个类别或多个 IoU 阈值求平均。具体平均方式由 VOC、COCO 等评价协议决定。

## 2. 目标检测必须解决哪些设计问题？

目标检测的任务定义长期稳定，但“怎样得到这一组目标”并没有唯一答案。检测模型的主要差别，可以还原成下面四个设计问题。

### 2.1 从哪里产生目标预测？

模型首先要决定：应该从哪些位置开始寻找目标？

- **候选区域（Region Proposal）**：先找出一批可能包含目标的区域，再逐个判断里面是什么。
- **密集位置（Dense Location）**：直接在特征图的许多位置同时预测，目标可能出现在哪里，就从哪里输出结果。
- **[目标查询（Object Query）](#_4-2-object-query-与匈牙利匹配)**：准备一组可学习的查询，让每个查询尝试寻找一个目标。

密集位置并不是说 CNN 一开始就知道“这里有一个目标”。CNN 先把图像变成特征图，检测头再让特征图上的许多位置分别输出类别分数和边界框。有些检测器还会单独输出目标存在概率（Objectness）。

```text
图像 → CNN 特征图 → 检测头
                   ├── 这里有没有目标？
                   ├── 目标是什么类别？
                   └── 边界框在哪里？
```

训练数据只需要提供真实类别和真实框，比如我们要检测车辆，只需要标注车的整体，不需要标注车轮、车窗等局部特征。训练时，[标签分配（Label Assignment）](#_2-3-预测怎样与真实目标对应)会根据真实框的位置、大小或与 [Anchor](#_2-2-边界框从哪里开始预测) 的 IoU，选择哪些特征图位置负责这个目标：

- 被选中的位置是正样本，学习目标类别和边界框。
- 没有负责目标的位置通常学习背景。
- 分类损失和边界框损失通过反向传播，一路更新检测头、Neck 和 CNN Backbone。

CNN 为了降低最终损失，会逐渐学到对检测有用的轮廓、纹理和整体形状，但这些中间特征不需要人工逐一标注。

检测器通常还会使用多层特征图：高分辨率特征图更适合小目标，低分辨率特征图感受野更大，更适合大目标。同样，人不需要为每个尺度重新制作标签，由标签分配规则决定哪些尺度和位置负责学习当前目标。

它们不是三个不同的任务，而是产生预测的三种方法。前两种主要来自 CNN 检测器，目标查询则来自 [DETR 路线](#_3-3-集合预测-detr-到实时-detr)。

### 2.2 边界框从哪里开始预测？

知道从哪里产生预测后，还要决定边界框怎样得到。

一种经典方法是预先在特征图上放置许多参考框，这些参考框叫做 **锚框（Anchor Box）**。同一个位置可以放置高、矮、宽、窄等不同形状的 Anchor，模型再预测：

```text
这个 Anchor 对应什么类别？
它应该向哪里移动？
它的宽和高应该怎样缩放？
```

这种方法叫做 **Anchor-based**。它给边界框回归提供了明确起点，模型不必从零预测整个框；但 Anchor 的大小、长宽比和数量需要设计，也会产生大量重复候选框。

后来出现了 **无锚框（Anchor-free）** 方法。它不再预设这些参考框，而是从特征图上的点、目标中心区域或参考点出发，直接预测目标边界。

例如[全卷积单阶段目标检测器（Fully Convolutional One-Stage Object Detection，FCOS）](https://arxiv.org/abs/1904.01355)会让目标内部的一个点预测到边界框四条边的距离：

$$
(l,t,r,b)
$$

Anchor-free 减少了 Anchor 的超参数，但没有省掉整个检测过程。模型仍然要确定哪些点负责哪些真实目标，也仍然可能对同一个目标产生多个预测。

因此，Anchor-based 和 Anchor-free 回答的是“边界框从哪里开始预测”，它们不能和“两阶段、单阶段”并列。一个单阶段检测器既可以使用 Anchor，也可以不使用 Anchor。

### 2.3 预测怎样与真实目标对应？

假设图里只有 3 个真实目标，模型却产生了 1000 个预测。训练时必须先回答：每个预测应该学习谁？

```text
预测 A → 真实目标 2
预测 B → 背景
预测 C → 真实目标 1
……
```

这个过程叫做**分配与匹配（Assignment and Matching）**。常见做法可以分成两类：

- **一对多匹配（One-to-many）**：一个真实目标可以分配给多个预测，共同提供训练信号。
- **一对一匹配（One-to-one）**：一个真实目标只和一个预测配对，其余预测学习“无目标”。

传统的候选区域检测器和密集检测器大多使用一对多匹配；DETR 使用[匈牙利匹配](#_4-2-object-query-与匈牙利匹配)建立一对一关系。

### 2.4 重复预测怎样处理？

一对多匹配会让多个预测同时学会寻找同一个目标，因此预测时也可能出现多个高度重叠的框。

传统方法使用 **非极大值抑制（Non-Maximum Suppression，NMS）** 删除重复结果：先保留置信度最高的框，再删掉与它高度重叠的低分框。

另一种方法是在训练时使用一对一匹配，让模型直接学习“一个目标只输出一个结果”。这种端到端集合预测可以不依赖 NMS。

所以 NMS 不是目标检测任务规定的固定步骤。它是“一对多预测怎样去重”的经典答案，而一对一检测器可以选择直接输出最终集合。

## 3. 目标检测算法的演进

理解了上面四个设计问题，再看论文演进就不会只剩下“两阶段”和“单阶段”两个名字。每条路线都在重新回答：预测从哪里来、怎样匹配、怎样去重。

### 3.1 候选区域驱动：R-CNN 到 Faster R-CNN

早期深度学习检测器延续了“先找区域，再识别区域”的思路。

[R-CNN](https://arxiv.org/abs/1311.2524) 先用传统算法生成大约两千个候选区域，再让 CNN 分别提取每个区域的特征，最后完成分类和边界框修正。它把 CNN 真正带入了目标检测，但同一张图要重复运行许多次 CNN，训练和预测都很慢。

[Fast R-CNN](https://openaccess.thecvf.com/content_iccv_2015/html/Girshick_Fast_R-CNN_ICCV_2015_paper.html) 先对整张图计算一次特征图，再从共享特征图中取出每个候选区域的特征。重复计算少了，但候选区域仍由网络外部的传统算法产生。

[Faster R-CNN](https://arxiv.org/abs/1506.01497) 又加入 **区域建议网络（Region Proposal Network，RPN）**，让神经网络自己产生候选区域。至此，“候选区域生成”和“区域分类回归”被放进同一个可训练框架：

```text
图像 → 共享特征 → RPN 产生候选区域 → 候选区域分类并修正边界框
```

因为它先产生候选区域，再识别和修正区域，所以被称为**两阶段检测器（Two-stage Detector）**。这条路线通常重视检测精度，也成为检测与实例分割的重要基础。

### 3.2 密集预测：SSD、YOLO、RetinaNet 与 FCOS

候选区域路线把检测分成两步，而另一条路线选择直接在特征图上同时预测类别和边界框。

[YOLO](https://arxiv.org/abs/1506.02640) 把目标检测写成一次前向计算完成的回归问题，不再为每个候选区域单独运行分类器。[SSD](https://arxiv.org/abs/1512.02325) 则在多个尺度的特征图上密集预测，让不同分辨率的特征负责不同大小的目标。

```text
图像 → 特征图 → 大量位置同时预测类别和边界框
```

这类方法没有独立的候选区域分类阶段，因此被称为**单阶段检测器（One-stage Detector）**。它们减少了中间步骤，速度快，很适合实时检测，但密集预测也产生了新的问题：绝大多数位置都是背景，简单样本远多于真正有目标的位置。

[RetinaNet](https://arxiv.org/abs/1708.02002) 用 [Focal Loss](../LossFunction/04_FocalLoss.md) 降低大量简单背景样本对训练的影响，让单阶段检测器的精度显著提升。它的重要性不在于成为一个新任务，而在于解决了密集检测里的类别不平衡问题。

[FCOS](https://arxiv.org/abs/1904.01355) 继续简化边界框的起点：不再预设 Anchor，而是让目标内部的特征点直接预测到边界框四条边的距离。它证明了单阶段密集检测不一定依赖 Anchor。

后来的实时检测器吸收了多尺度特征、Anchor-free、解耦检测头和更灵活的标签分配等设计。现代 YOLO 仍属于单阶段实时检测路线，但它已经不是早期 YOLO 的原样重复，而是在不断融合新的检测组件。

### 3.3 集合预测：DETR 到实时 DETR

2020 年，[检测 Transformer（Detection Transformer，DETR）](https://arxiv.org/abs/2005.12872) 换了一种方式理解目标检测：模型不再密集地产生大量框并使用 NMS 去重，而是直接预测一组目标。

```text
图像特征 + 一组 Object Query
→ Transformer
→ 一组类别和边界框
```

这里的 [Object Query](#_4-2-object-query-与匈牙利匹配) 是一组可学习向量。每个 Query 通过 Transformer 读取图像特征，再尝试输出一个目标的类别和边界框；没有找到目标的 Query 输出“无目标”。

训练时，DETR 使用[匈牙利匹配](#_4-2-object-query-与匈牙利匹配)，在预测和真实目标之间建立一对一关系。一个真实目标只分配给一个预测，因此模型可以直接学习输出不重复的结果，不再需要 Anchor 和 NMS。

原始 DETR 的问题也很明显：收敛慢，对小目标不够友好。[Deformable DETR](https://arxiv.org/abs/2010.04159) 让注意力只关注少量关键采样点，并引入多尺度特征，使训练更快、小目标检测更好。

[DINO](https://arxiv.org/abs/2203.03605) 继续改进 Query 初始化、去噪训练和边界框逐层优化，成为 DETR 路线中很有代表性的检测器。这里的 DINO 指目标检测模型，不是图像分类文章里讲的自监督 DINO。

[RT-DETR](https://arxiv.org/abs/2304.08069) 则把这条路线推向实时检测。它说明“端到端集合预测”和“实时检测”不再互相排斥：DETR 路线也可以面向低延迟部署。

### 3.4 不同路线开始融合

早期目标检测很容易分成两边：

- Faster R-CNN：两阶段、候选区域驱动。
- YOLO / SSD：单阶段、密集预测。

DETR 出现后，又增加了“一对一集合预测”这套方法。继续发展下去，路线之间开始互相吸收设计：实时检测器引入一对一匹配和端到端输出，DETR 检测器也在追求更快的训练与预测速度。

以 Ultralytics 官方的 [YOLO26](https://docs.ultralytics.com/models/yolo26/) 为例，它仍保留 YOLO 的实时检测定位，但默认使用一对一检测头直接输出结果，不需要 NMS；训练时还保留一对多检测头提供更丰富的监督。它说明现代检测器已经可以同时吸收密集检测和集合预测的设计。

这不代表所有检测器最终都会变成同一种结构，而是说明“两阶段还是单阶段”已经不足以描述全部变化。还要同时看边界框起点、匹配方式和去重方式。

### 3.5 抽象总结：变的是怎样得到一组目标

| 演进路线       | 预测从哪里来       | 典型匹配方式    | 重复结果处理 | 代表模型                        |
| -------------- | ------------------ | --------------- | ------------ | ------------------------------- |
| 候选区域驱动   | 候选区域           | 一对多          | NMS          | R-CNN、Fast R-CNN、Faster R-CNN |
| 单阶段密集预测 | 特征图上的大量位置 | 一对多          | NMS          | SSD、YOLO、RetinaNet、FCOS      |
| 端到端集合预测 | Object Query       | 一对一          | 直接输出集合 | DETR、Deformable DETR、DINO     |
| 路线融合       | 根据模型组合       | 一对多 + 一对一 | 可选 NMS     | YOLO26                          |

这些模型改变的是产生预测、分配监督和删除重复结果的方法，但目标检测的算法抽象没有变：

```text
输入一张图像
→ 输出数量不固定的一组目标
→ 每个目标包含类别、位置和置信度
```

## 4. 总结和扩展

### 4.1 NMS 为什么能够删除重复框？

假设同一辆车周围出现了三个高度重叠的预测框，置信度分别是 0.95、0.88 和 0.76。NMS 的处理过程是：

1. 保留置信度最高的 0.95 框。
2. 计算其他框与它的 IoU。
3. 删除 IoU 超过阈值的低分框。
4. 对剩余框继续重复这个过程。

最终，同一个目标附近通常只留下一个高分框。PyTorch 在 `torchvision.ops.nms` 中提供了 [NMS 算子](https://docs.pytorch.org/vision/master/generated/torchvision.ops.nms.html)。NMS 简单有效，但阈值会影响结果：

- 阈值太低，距离很近的两个真实目标可能被误删；
- 阈值太高，同一个目标又可能留下多个框。

### 4.2 Object Query 与匈牙利匹配

原始 DETR 只有图像输入，不使用文字，也不是 CLIP 这样的多模态模型。它先用 CNN 提取图像特征，再用 Transformer 和 **目标查询（Object Query）** 寻找目标：

```text
图像 → CNN → 特征图 → Transformer 编码器 → 图像特征 ─────────┐
                                                            ├→ Transformer 解码器 → 类别和边界框
可学习的 Object Query ───────────────────────────────────────┘
```

CNN 特征图保留了不同位置的视觉信息，Transformer 编码器让这些位置交换信息，从整张图理解它们之间的关系。Transformer 解码器再让 Object Query 读取整合后的图像特征。

Object Query 不是文字，也不是“车”“人”这样的类别名称，而是模型训练出来的一组向量。每个 Query 都尝试寻找一个目标，并输出：

```text
这个目标是什么类别？
它的边界框在哪里？
```

假设模型准备了 100 个 Query，一张图里只有 3 个真实目标。最终可以有 3 个 Query 分别找到这 3 个目标，其余 Query 输出“无目标”。Query 没有固定分工：第一个 Query 不一定总是找人，第二个 Query 也不一定总是找车。

训练时必须决定哪一个 Query 学习哪一个真实目标。DETR 会计算每个预测与每个真实目标的匹配代价，主要包括：

$$
C_{match}=C_{class}+\lambda_1 C_{L1}+\lambda_2 C_{GIoU}
$$

- $C_{class}$：预测类别是否接近真实类别。
- $C_{L1}$：预测框坐标与真实框相差多少。
- $C_{GIoU}$：预测框与真实框的重叠和相对位置是否接近。

有了所有匹配代价后，**匈牙利匹配（Hungarian Matching）** 会寻找一组一对一配对，让整体代价尽可能小。

例如现在有预测 1、预测 2，以及真实目标 A、真实目标 B。它们之间的匹配代价是：

```text
预测 1 → A：代价 1
预测 1 → B：代价 4
预测 2 → A：代价 2
预测 2 → B：代价 100
```

因为是严格的一对一匹配，一个预测只能负责一个真实目标，一个真实目标也只能交给一个预测，所以只有两种合法组合。

**组合一：**

```text
预测 1 → A，代价 1
预测 2 → B，代价 100
总代价 = 1 + 100 = 101
```

**组合二：**

```text
预测 1 → B，代价 4
预测 2 → A，代价 2
总代价 = 4 + 2 = 6
```

单独看预测 1，它最适合 A；但是把 A 交给预测 1 后，预测 2 就只能匹配非常不合适的 B。匈牙利匹配会比较整体结果，最终选择总代价更小的组合二，而不是让每个预测各自做一次局部选择。

匹配完成后：

- 配对成功的 Query 学习对应目标的类别和边界框。
- 没有配对的 Query 学习“无目标”。
- 一个真实目标只交给一个 Query，模型因此学会减少重复输出。

这里还要和 [AP 评价中的预测框匹配](../EvaluationMetrics/11_AP.md#_1-1-怎样确定-tp、fp-和-fn)区分开：

- **匈牙利匹配**：DETR 训练时使用，根据类别和边界框代价分配监督关系。
- **AP 匹配**：模型预测完成后使用，根据置信度顺序和 IoU 阈值判断 TP、FP、FN。

它们都在建立预测和真实目标的对应关系，但一个负责训练，一个负责评价。

### 4.3 工程生态：Torchvision、MMDetection 与 Ultralytics

目标检测已经形成了成熟的工程生态：

- [Torchvision](https://docs.pytorch.org/vision/master/models.html#object-detection) 提供 Faster R-CNN、SSD、RetinaNet、FCOS 等经典检测模型，适合直接使用 PyTorch 官方实现。
- [MMDetection](https://github.com/open-mmlab/mmdetection) 把 Backbone、Neck、Detection Head、损失和数据流程拆成可配置组件，适合研究和比较不同检测路线。
- [Ultralytics](https://docs.ultralytics.com/tasks/detect/) 提供 YOLO 系列的训练、预测和导出接口，工程部署流程比较完整。

这些工具箱不是新的目标检测算法。它们的作用是把论文模型、训练配置、数据集和部署接口组织到同一套工程框架里，让使用者不必从零实现整条检测流程。
